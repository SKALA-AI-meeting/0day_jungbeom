## 2026-10-21 최종본 완료·DM 보고·명시적 종료 (제안)

- **합의한 기본 흐름:** 과제/최종본 탭의 완료 버튼은 최종본을 한서윤에게 전달하고 그 사실을 알린다. 화면은 한서윤 1:1 DM으로 주담당을 안내한다. 주담당이 직접 완료 내용을 보고하면 한서윤이 DM에서 확인·격려 답장을 보내고, 그 답장에 달린 종료 버튼을 주담당이 눌러 세션을 끝내고 디브리핑으로 이동한다. 완료 버튼이 보고 메시지를 자동 작성·전송하지 않으며, 제출 뒤 별도의 팀 채널 보고 재촉은 없앤다.
- **현행 규칙과 차이:** PRD는 제출 후 보고 요청을 보내고 `report` 분류 또는 5분 경과 시 종료한다. 한서윤의 답장과 종료 버튼은 종료 조건이 아니다. 특히 11L/12에 보고 요청이 이미 나갔으면 제출 시 즉시 종료하는 규칙도 새 순서와 충돌한다.
- **보존할 관찰 원칙:** 정직/공정한 보고는 주담당이 한서윤 DM에 실제로 쓴 내용으로 판단한다. 최종본 전달 알림이나 팀장 답장을 주담당의 보고로 간주하지 않는다.
- **세부 결정 대기:** 미보고, 팀장 답장 실패, 종료 버튼 미클릭·재접속, 자동 제출 시의 안내와 처리, 현행 5분 제한의 변경 여부를 정한다. 11L/12 제출 전 보고 요청 카드의 유지 여부와 시점·관찰 창도 정한다. PRD, 공용 계약, 상태 전이, 에이전트·API·워커, UI 및 전체 흐름 테스트에 영향을 준다.
- **2026-10-21 반영(문서 턴):** PRD·계약·상태 전이에 반영했다. 세부는 아래로 정한다. 완료 시각 기준 5분 자동 종료는 사용자 결정(fallback). 01:50 보고 요청 카드 유지와 조기 완료 시 DM 실행은 제안(사용자 확정 범위 밖). 할 일 필수 조건 없음과 섹션 담당 분리는 사용자 결정. 할 일 담당과 섹션 담당 불일치 방지, 확인 답장 실패, 최소 조건 유지(CX-04)는 TBD.
- **상태:** PRD 반영 · 세부 일부 TBD · 팀 공유 필요. 팀 공유는 후속 절차다. 지원자 관찰과 세부 근거는 `docs/candidate-experience-fixes.md`의 CX-12 참조.

## 2026-10-20 인성 5요소·미션 단위 재설계 (제안)

### 1. 초점

평가 기준을 "이 사람과 같이 일하면 상대가 편한가"로 둔다. 관찰할 것은 사건에 대한 반응이 아니라 **동료가 지원자에게 무언가를 필요로 하는 순간(결정·답·상태·다시 정리된 방향·들어 줌·인정)에 그것을 주는가**다. 실력(오류 발견, 산출물 품질)은 점수에 넣지 않는다. AI 활용 관찰은 지금처럼 점수 없이 기록만 한다.

### 2. 요소와 카드 (요소당 최대 2장, 전부 선택 시 7장)

| 요소 | 카드 | 시점 | 동료가 필요한 것 | 같이 일하기 좋은 행동 (평가표 항목 초안) |
|---|---|---|---|---|
| 계획성/꼼꼼함 | 분업·계획 | L/12 | 결정 | 파트를 빠짐없이 배정 · 누가·언제까지·어떤 순서인지 말함 · 동료 파트에 필요한 내 자료를 확인해 줌 · 팀장 조건(마감·분량·대상)을 되짚음 → 2항목 |
| | 중간 점검 (동료 초안 공유, 지금 texture) | 중간 슬롯 2 | 반응 | 동료 초안을 읽고 반응함 · 분업 때 확인한 자료를 실제로 챙겨 줌 → 2항목 |
| 협업/조율 | 도움 요청 | 중간 슬롯 1 | 답 | 응답함 · 바로 돕거나 시점을 제안함 · 제안한 시점에 실제로 옴(약속 이행) → 2항목 |
| | 반대 의견 (리뷰 시 동료가 근거를 들어 지원자 결정에 다른 의견) | 3L/4 | 들어 줌 | 의견에 답함 · 근거로 설명하거나 수용(무시·강행 아님) · 비난 없음 · 동료 파트에 피드백 줌 → 2항목 |
| 책임감/성실성 | 내 자료 지연 | 중간 슬롯 3 | 상태 | 공개 전에 먼저 알림 · 동료 파트에 미치는 영향을 언급 · 대안 제시 · 팀장이 보는 곳에 알림 → 4항목 |
| 적응성/유연성 | 팀장 방향 변경 | 중간 슬롯 4 | 다시 정리된 방향 | 문서에 반영 · 불만을 동료에게 쏟지 않음 · 동료 파트에 무엇이 바뀌는지 다시 정리해 줌 · 범위·일정 재조정 언급 → 4항목 |
| 정직/공정한 보고 (선택) | 마감 보고 (팀장 "다 됐다고 전해도 되죠?" 압박 포함) | 11L/12 또는 제출 중 먼저 | 인정 | 동료가 한 일을 동료 것으로 말함 · 안 된 것을 숨기지 않음 · 동료가 쓴 파트를 자기 것으로 말하지 않음 · 요청 후 N분 안에 보고 → 4항목 |

- 기존 존중·소통 카드(동료 파트 정책 위반)는 삭제한다. 오류를 찾는 건 실력이다. 반대 의견 카드는 정답이 없는 "의견"이라 듣는 태도만 보인다.
- 요소 점수 = 카드 항목 합. 요소당 항목 4개는 유지(2+2 또는 4).
- 미선택 시: 계획성 → 분업·초안 공유는 흐름 카드로 남고 점수 없음. 협업 → 도움 요청 없음, 리뷰는 반대 의견 없이 공유만. 책임감 → 자료 처음부터 공개. 적응성 → 변경 없음. 정직 → 보고 요청은 흐름 카드.

### 3. 배치 (세션 길이 L, 기본 120)

- 고정: 킥오프 0, 분업 L/12, 리뷰 3L/4, 보고 11L/12(또는 제출 시).
- 중간 슬롯 4개를 L/4~3L/4에 균등 배치(120분: 30·45·60·75). 순서 고정: 도움 → 중간 점검 → 지연 → 변경. 미선택 카드의 슬롯은 비우지 않고 남은 카드로 다시 균등 배치.
- 책임감 자료 지연은 L/12(10분)로 줄여 창 안에 공개되게 한다(기존 L/8).
- 관찰 창은 **카드 단위**: 카드 실행부터 다음 요소 카드(어느 요소든)까지. 마지막 창은 제출·종료까지. 약속 이행처럼 창을 넘는 행동은 관련 카드 연결(related_card)로 판정에 허용한다.

### 4. 미션과 산출물 (실제 리모트 협업처럼)

- 카탈로그를 미션 단위(`scenarios/missions/<id>/`: 회사·문서·파트·카드·페르소나·프롬프트)로 나누고 채용 건에 `mission_id`를 둔다. MVP는 기획안 미션 하나만 완성하고, 개발 미션은 산출물을 문서형(설계 문서)으로 제한해 시간이 남으면 추가한다. 같은 채용 건 안에서만 비교한다는 원칙은 그대로.
- **문서 주고받기 모델**(2026-10-20 밤 결정, 상세 `docs/frontend/design-direction.md`): 공유 문서 한 장 대신 각자 자기 파트 문서를 쓰고 보낸다(버전 v1, v2…). 받은 쪽은 가운데 패널에서 열어 보고 문서에 매인 답글로 피드백한다. 리드만 **최종본**을 가지며, 킥오프에서 팀장이 준 최종 아웃풋 템플릿에 맞춰 받은 문서를 가져와(출처·버전 기록) 합치고 고친 뒤 제출한다. 낙관적 잠금·섹션 작성자 추적은 필요 없다.
- 동료는 중간 점검 때 초안 v1을 보내며 리드 진행을 묻고, 리뷰 때 리드 문서를 보자고 청한 뒤 고정 내용의 다른 의견을 낸다. "같이" 파트는 동료가 골격 v1을 보내고 리드가 최종본에서 고친다.
- 팀장 DM 상시. 과제 맥락 질문에는 답하고 정답·판단 요청은 리드에게 돌린다. 보드 카드에 "언제까지" 선택 입력.
- 동료 페르소나 가치 "상대의 결정을 존중하고 따른다"를 "근거를 들어 한 번 다른 의견을 내고, 리드가 정하면 따른다"로 바꾼다. 반대 의견 카드는 지원자가 쓴 내용을 읽고 말하되, 3L/4까지 지원자 작성이 없으면 카탈로그에 정한 대체 대상(분업 때 정한 방향 또는 킥오프 기본 가정)에 대해 말한다.
- 동료 진행 공유 texture를 1~2개 더 둔다(관찰 없음).

### 7. 설계 수준 결정 (오케스트레이터, MVP 범위 안)

| 주제 | 결정 |
|---|---|
| 중간 슬롯 공식 | 기존 유지: 선택된 중간 카드 N개를 L/4 + i·(L/2)/N (i=0..N-1). 순서 도움 → 중간 점검 → 지연 → 변경. 계획성 미선택이면 초안 공유는 슬롯 없이 L/2 texture. 킥오프의 인터뷰 공유 예정 시각은 조립된 지연 카드 시각 |
| division_min | 유지(2번 지원자, 4·5 중 하나 동료 단독). 책임감·정직 카드의 전제. "지원자 단독 파트"는 분업에서 candidate인 파트이며 UI 권한이 아니라 페르소나 규칙으로만 보호 |
| 파트 의존 관계 | 카탈로그에 명시: 3번(핵심 기능)은 2번(인터뷰 근거)에 의존. 계획성 "동료 파트에 필요한 내 자료 확인"과 책임감 "동료 영향 언급"의 근거 |
| 반대 의견 카드의 공정성 | 동료의 반대 내용을 카탈로그에 고정(핵심 기능 방향에 대한 고정 의견 1개 + 지원자가 같은 방향이면 쓰는 두 번째 고정 의견). 지원자 작성물은 "어느 문장에 대해 말할지"에만 쓰고 의견 자체는 바뀌지 않음. "말투만 생성" 원칙 유지. 작성 없음 판정은 3번 파트 50자 미만 |
| 페르소나 "한 번 반대" | 카드 실행에서만. 카드 밖에서는 지금처럼 결정을 따름 |
| 선점 금지 재정의 | 계획성 창: 동료가 일정·순서를 먼저 정하지 않음. 중간 점검 창: 지원자 자료를 재촉하지 않음. 책임감 창: 대안·팀장 보고 먼저 안 함(기존). 적응성 창: 바뀐 방향 정리를 먼저 하지 않음(기존). 정직 창: 팀장에게 직접 보고하거나 자기 기여를 먼저 말하지 않음 |
| 기여 판정 | 문서 주인과 공유 이력으로 판정(문서마다 주인 하나). 최종본 섹션의 출처(문서·버전·리드 편집 여부)를 리포트에 표시 |
| 정직 "미완료 숨기지 않음" | 품질 판단 없이 사실만: 빈 파트, 보드 상태 done 아님, 적응성 카드 후 revision 없음. 이 사실 목록을 observe 입력으로 LLM이 보고 문장과 대조 |
| 창 밖 근거 | 메시지 타입만 related_card로 허용(약속 이행·지연 대응). revision·doc_view는 창 안만. 같은 시각의 흐름 카드+요소 카드는 요소 카드 기준으로 창을 연다 |
| 문서 충돌 | 없음(문서 주인 하나). 데이터 모델: documents(주인·파트·버전) + document_shares + document_opens + final_document(섹션별 출처) |

| 이름 정리 | MVP 이후 후보 "공정성(분업 균형)"은 삭제해 "공정한 보고"와 겹치지 않게 함 |

### 8. 기획 수준 결정 (사용자)

1. **제출과 보고의 순서.** 제출 버튼 → 팀장 보고 요청 → 지원자가 보고하거나 5분이 지나면 종료. 11L/12에 이미 보고 요청이 나갔으면 제출 시 바로 종료. 정직 미선택이면 보고 요청은 흐름 카드로 같은 흐름을 타되 점수 없음. 세션 상태에 `reporting`(제출 후 보고 대기) 단계가 생기고, 시간 만료 자동 제출도 같은 흐름을 탄다.
2. **호칭: "리드" → "주담당".** 지원자는 분업·재지시·최종본 통합·보고를 맡되 동료와 같은 팀원이다. 팀장 킥오프: "이번 건은 OO님이 주담당으로 맡아 도현님과 함께 정리해 주세요." PRD·설계 문서·카탈로그(`candidate_role`)·프롬프트·안내 화면·리포트 문구를 반영 때 한 번에 바꾼다.
3. **문서 주고받기 모델, 최종본 템플릿, 동료의 문서 확인 요청, 보드 "언제까지", 팀장 DM 상시.** 상세는 `docs/frontend/design-direction.md`의 "결정" 절.
