# 하네스 8요소

| 요소 | 구현 위치 | 수치·규칙 | 확인 방법 |
|---|---|---|---|
| Instructions | 미션 폴더 `scenarios/missions/<id>/prompts/` 페르소나별 system prompt(manager, colleague, assistant), `common_rules.md`(판정 금지, 문서명 인용, 평가 기준 질문 안내문, 기능 설명만 하고 평가 대상 행동을 유도하지 않음, 시각은 오피스 시계로만 말함), `guard_patterns.yaml`(판정 패턴과 압박 문구 패턴). 행동 계약은 agent/design.md 표. 카드 `brief`·`text` 주입(카드 내용은 scenario-model.md) | 프롬프트·guard 패턴은 catalog_version 해시에 포함되고 본문이 `positions.scenario`에 복사되어 채용 건에 고정. 실행은 scenario의 복사본을 쓴다 | 프롬프트 리뷰, 유출·미래 암시·역할 사칭 질문 테스트 |
| Tools | MCP 클라이언트 2개(`langchain-mcp-adapters`). 그래프별 허용 목록(contracts.md: 동료 4개, 팀장 3개(search_documents 포함), 어시스턴트 2개), session_id는 그래프가 주입 | 응답당 도구 호출 3회, 검색 top 3, 메시지 조회 50개, 도구 결과 2k자 절단 | respond 노드 로그, 허용 밖 도구 호출 거부 테스트 |
| Context | 페르소나별 허용 목록: 동료 = 팀·동료 DM 최근 30개 + 요약 1개 + 보드 + 지원자가 **보낸 버전**의 문서(`get_shared_documents`) + 자기 문서 + 실행 중 카드 brief(collab_disagree는 카탈로그 고정 의견 `fixed_opinions`와 대체 대상 규칙) + rag 청크 3개. 팀장 = 팀 채널 + 팀장 DM + rag 청크(회사 문서의 뜻 질문. 정답·판단 요청은 주담당에게 돌림). 어시스턴트 = 자기 대화 + 공개 문서 청크. observe(honesty_report) = 창 안 행동 + 규칙이 만든 **정직 사실 입력**(공유 이력, 최종본 섹션 출처, 보드 상태, 빈 섹션, 미완료 파트, 적응성 카드 이후 주담당 문서 revision·share 유무). 모든 페르소나 입력에 현재 오피스 시각(09:00 + t_min × 120/L)과 마감 11:00을 넣는다. **어느 페르소나에도 넣지 않는 것**: 아직 오지 않은 카드, 관찰 레이블·metrics·사실 입력, 어시스턴트 대화(동료·팀장에게), 미공개 문서, 지원자가 보내지 않은 문서 내용, `notice` 채널 알림 | 호출당 입력 6k 토큰, 초과 시 오래된 메시지를 요약으로 접음 | 토큰 메타, 미래 상황 유도 질문 3건·미공개 문서 질문·역할 사칭 질문·보내지 않은 문서 질문 픽스처 |
| State·Memory | LangGraph PostgresSaver. thread `session:{id}`, `assistant:{id}`, 워커 `report:{id}` | 자극마다 체크포인트. 재시작 시 fired 이벤트 재실행. State의 `current_card`가 열린 관찰 창(planning_division은 세션 시작부터) | restart 대본 |
| Agent Loop | recursion_limit 20, 분업 되돌림 1회(division_min 위반 시, 이유는 의존 관계), 업무 중 재분업 1회(adaptability_change 뒤), 어시스턴트 60회/세션, 세션 토큰 예산 300k(입력+출력, 재시도 포함), `ends_at` 도달 시 메시지 없이 자동 제출 → 한서윤 고정 답장 → 즉시 completed(한서윤에게 보내기와 같은 처리) | 한도 초과는 고정 안내문. 예산 소진 뒤 페르소나 자유 응답은 안내문으로 대체하고 카드는 brief 없이 규칙 문장으로 계속 발행. 한도는 세션 단위, 초기화 없음 | e2e 단언, agent_runs.usage 합산 |
| Guardrails | `guard`: 점수·합격·순위·연출·평가 기준 패턴 → 고정 안내문 치환. 압박 문구 패턴("다 됐다고 전해도" 류, 결정적 문자열·정규식 검사)이 LLM이 만든 팀장·동료 메시지에 있으면 1회 재생성 → 그래도 있으면 페르소나별 안전 문구로 교체(고정 문구 카드 honesty_report는 검사 대상 아님). 입력 마스킹: 전화번호·이메일. 선점 금지(카드 창별, persona.yaml `must_not_preempt`)는 프롬프트 + 픽스처로 확인. 사람 승인: 리포트 그래프 interrupt → 검토 완료가 같은 thread 재개 | 패턴 목록은 prompts 트랙이 관리. 승인 전 final 저장은 api가 409로 차단 | guard 단위 테스트, 선점 유도 픽스처, 승인 e2e |
| Recovery | LLM 래퍼: 타임아웃 30초, 재시도 2회(1·3초) → `FallbackText` | 일반 응답 실패: 고정 문장 저장, llm_failures+1. 필수 카드 실패: 이벤트 attempts+1로 재실행(최초 포함 총 3회). 동료 문서 보내기(`send_document`) 실패: 같은 run_id로 1회 재시도, 그래도 실패면 카드 status=failed(같은 3회 규칙)이고 이벤트 행에 `document_missing`을 남겨 그 문서에 의존하는 항목은 사유 `document_missing`으로 기록 없음. llm_failures 연속 3회 또는 카드 3회 실패 → 세션 failed. 성공 시 카운터 0 | 강제 실패 주입 테스트 |
| Observability | LangSmith trace(LLM 호출의 metadata.run_id·tags; 그래프 config의 메타데이터 키는 `agent_run_id` — `run_id`를 쓰면 LangGraph가 같은 run_id 재호출을 끝난 실행으로 보고 건너뛴다), `agent_runs.usage`(run별 llm_calls, retries, tokens_in/out, latency_ms, tool_calls), `messages.meta`(응답별 토큰·지연·모델), `reports.usage`(워커), 구조화 로그에 run_id | 세션 비용 = agent_runs.usage + reports.usage 합. 접수→응답 지연 = message.ack 시각과 응답 message.new 시각 차 | trace 링크, e2e summary의 비용·지연 표 |

실패 유형별 폴백 형태: 페르소나 응답 → 고정 문장. 압박 문구 검사 2회 실패 → 안전 문구. 분업 분류 → "수락"으로 간주하지 않고 재질문 1회 후 마지막 안 확정. 관찰 분류 → label null(관찰 없음)로 기록(metric 항목은 계산). 동료 문서 보내기 → 1회 재시도 후 카드 실패(document_missing). 어시스턴트 → "잠시 후 다시 시도해 주세요".

## 역할별 모델 (2026-10-20)
역할 5개(동료·팀장·관찰 분류·어시스턴트·리포트)는 env `MODEL_<역할>`을 읽고 비어 있으면 `OPENAI_MODEL`을 쓴다. 키는 모델 id로 고른다(gpt-4o-mini → 제한 키, 그 외 gpt-* → 개인 키, gemini-* → Gemini 키, OpenAI 호환 엔드포인트). 규칙은 공용 LLM 래퍼 한 곳. 상향 규칙은 `docs/decisions.md`.
