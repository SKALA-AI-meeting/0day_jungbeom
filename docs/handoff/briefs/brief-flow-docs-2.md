# 브리프: 지원자 흐름 재정의 문서 반영 (flow-docs 2차)

2026-10-21 사용자 결정. 지원자 실사용 점검(`docs/candidate-experience-fixes.md` CX-01~13)과 `track/docs-flow` 독립 리뷰에서 나온 문제를 모두 해결하는 방향으로 PRD와 설계 문서를 정리한다. 원칙: 참여자 입장에서 실제 현업에서 있을 법한 흐름, 크게 바뀌는 서비스 기능만 사용자와 결정하고 나머지는 가장 단순한 구조로 정한다.

## 확정 결정

| ID | 결정 |
|---|---|
| F1 할 일 섹션 연결 | 할 일은 5개 섹션 중 하나에 반드시 연결한다. `tasks.section_part_no` NOT NULL, `POST /sessions/{id}/tasks`에서 필수. 한 섹션에 여러 할 일 가능 |
| F2 빈 보드·분업 공유 (CX-02·04) | 보드는 빈 상태로 시작, 주담당이 할 일 생성·섹션 연결·담당 지정 후 **분업안 공유**로 팀 채널에 올린다. `division_min`은 현행 유지. 필수 담당 조건은 처음부터 화면에 보이고, 공유 시 전체를 검증해 실제 위반된 섹션·할 일을 강조한다(마지막으로 편집한 카드에 오류를 붙이지 않음) |
| F3 종료 흐름 (CX-12 대체) | 완료 버튼 → **한서윤에게 보내기** 창(최종본 첨부, 자유 메시지 입력란은 선택, 안내·예시 문구 없음, "보내면 수정할 수 없어요"만 표시) → 보내면 메시지는 한서윤 DM에 `kind=report`로 저장 → 한서윤 **고정 답장** "받았어요, 수고하셨어요." → 즉시 `completed` → 디브리핑. `reporting` 상태, 종료 버튼(`finish`), `end_available`, 5분 fallback, LLM 답장 생성, 답장 실패 처리(D3), 보고 요청 채널 분기(D1)는 모두 제거한다. 2시간 자동 완료는 메시지 없이 제출되고 즉시 completed |
| F4 압박 DM (정직 요소) | 11L/12(120분 기준 10:50)에 한서윤이 **개인 DM**으로 고정 문구를 보낸다. 상황 설명과 진행 정도를 묻는 압박: "11시에 위에 올려야 해서요. 지금 어디까지 됐어요? 다 됐다고 전해도 되죠?" (D2 확정, 문구 다듬기는 허용). 이미 제출했으면 보내지 않는다. 팀 채널 재촉은 없다 |
| F5 정직 판정 근거 | 제출 메시지와 10:50 DM 이후 주담당이 한서윤 DM에 쓴 메시지만 근거. 보고 시간 기준(요청 후 N분, 완료 후 5분)은 없앤다. 평가표 4항목 중 시간 항목은 가장 단순한 사실 항목으로 바꾸고 decisions.md에 기록 |
| F6 금지 문구 (CX-03) | "다 됐다고 전해도 되죠?" 류의 압박 문구는 F4 고정 DM에만 나온다. LLM이 생성하는 팀장·동료 메시지는 결정적 검사로 금지 문구를 막는다(재생성 1회 → 실패 시 안전 문구) |
| F7 채널 역할 (CX-01) | 팀 채널은 분업·공동 결정·문서 공유, DM은 개인 도움 요청·개별 확인. 이도현의 시작 DM 인사는 없앤다. 이도현의 팀 채널 첫 인사는 준비됐다는 수준으로 짧게, 분업을 유도하지 않는다 |
| F8 오피스 시각 (CX-11·09) | 오피스 시각 09:00 시작·11:00 마감 고정. 압축 세션(6분 등)은 같은 비율로 매핑. 상단에 "오피스 시각 09:23 · 마감 11:00 · 1시간 37분 남음". 팀장·동료 발화, 자료 공개 예정, 채팅 타임스탬프, 마감 경고를 모두 이 시계로 표기. 예정된 지연은 지연 알림 전에 노출하지 않는다(현행 유지) |
| F9 행동 유도 금지 | 화면 안내와 에이전트 문구는 기능 설명만 한다. "먼저 할 일을 만들어 분업안을 공유하세요", "누가 뭘 했는지 적어 주세요"처럼 평가 대상 행동을 유도하는 문구를 쓰지 않는다 |
| F10 화면 (CX-08·05·13·06) | 채널 목록과 시각 표시는 유지하고, 메인 영역에서 대화·내 문서·보드·자료·어시스턴트를 탭으로 전환, 작업 탭에서 새 메시지 배지. 자료는 Markdown 서식 뷰어. 정보 밀도(CX-13)와 자료↔문서 참조(CX-06)는 탭 전환 뒤 기본안(상태별 요약, 펼침·접힘)으로 |
| F11 자료 문구 (CX-07) | 지난주 회의록이 이전 계획임을 알 수 있게 한 줄 맥락을 둔다 |
| F12 범위 밖 | 자료 탭 '기본 작업 흐름 예시'(D4)는 MVP에서 제외 |

## 리뷰가 남긴 문제 (반드시 해결)

1. `docs/common/contracts.md` 내부 계약이 분업 확정 시 동료 할 일을 doing, 리뷰 시 done으로 바꾸도록 요구한다. 할 일 0개인 정상 경로와 충돌하므로, 존재하는 할 일만 갱신하거나 섹션 담당·스냅샷 기준으로 바꾼다.
2. `docs/common/architecture.md`의 "같은 tasks를 채운다" 표현.
3. `docs/common/rubric.md`의 보고 점수 10분·`response_minutes` 기준 → F5로 대체.
