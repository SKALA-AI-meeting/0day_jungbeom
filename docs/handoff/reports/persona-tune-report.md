## 바꾼 것

| 무엇 | 어디 | 왜(기준선에서 본 것) |
|---|---|---|
| 호명 순서 규칙 `called_seats` | `rules.py` 규칙 3 | 분류 `addressed_to` 순서가 호명 순서와 달라("서지안님, 하람님 대신…" → [p2, p3]) 다른 자리가 먼저 답했다. 메시지에서 "이름님"으로 먼저 부른 자리부터 세우고, 분류가 놓친 호명도 넣는다. 카드 화자가 먼저인 규칙 2는 그대로다 |
| 정해진 안내 `notices.decide`와 `notice_triggers` | `fixed_phrases.yaml`, `graph.py` load·apply | 진행 질문에 아무도 방법을 답하지 않았고, 프롬프트만으로는 0.2에 그쳤다(문제 상황 단계에서 "네 개 중에서" 같은 틀린 안내도 나옴). 패턴에 걸리면 그 run 첫 화자의 본문을 (400 − 안내문 길이)로 먼저 자르고 그 본문으로 guard·stance_check를 돈 뒤, 게시할 때 안내문을 앞에 붙인다(guard·입장 폴백 문구여도 붙이고, 카드 고정 한 줄에는 붙이지 않음). 페르소나에는 `[정해진 안내]` 블록으로 이어질 말만 쓰게 한다. 화면 위치는 "화면의 '결정 사항'"만 말한다 |

## 남은 것·주의

- 문제 상황 카드 전 하람을 부르면 여전히 `stance_check=fallback`으로 "음… 저는 조금 더 들어 볼게요."가 나간다(입장 전에 "저도 동의해요"류를 말해 계획 밖이 됨). 답은 나가지만 내용이 약하다. `stance_fallback.yaml` 문구 손질은 이번 범위 밖으로 두었다.
- 발언이 여전히 길다(2~4문장, 200자 넘는 경우 많음). 안내문이 붙으면 더 길어진다. 길이는 지표에 없어 손대지 않았다.
- 소극형이 전체 질문(이름 없는 question)마다 첫 화자가 되는 규칙 3 때문에 "단계당 한 줄" 성향과 어긋나게 자주 말한다. 규칙 변경은 설계 결정이라 손대지 않았다.
- "한결님 말처럼…"처럼 언급만 해도 그 자리가 지명 응답 대상이 된다(의도한 단순화).
- 기준선 실행에 run error 1건이 있었다(같은 가짜 MCP 인자 오류, `get_material(query=…)`. 그 run의 발언 하나가 빠졌다). 튜닝 후 실행은 0건.
- 문서: main ed9f22a에 반영됨. 다만 `docs/agent/design.md` "정해진 안내"의 "(합쳐 400자 자르기)"는 이번 리뷰 반영으로 "본문을 (400 − 안내문 길이)로 먼저 자르고 검사 뒤 안내문 부착, 폴백에도 부착"으로 바뀌었다. 반복 재생성의 도구 예산 공유도 적어 두면 좋다.
