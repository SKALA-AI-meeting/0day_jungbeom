# G-M UI/UX 리뷰 — Day Zero 목업 (track/debate)

- 대상: `Day-0_zaeho.worktrees/debate` (291a15d), 기존 캡처 18장(지원자 10 + 관리자 8, PDF 포함) 전부 확인
- 직접 실행: 앱 사본을 scratchpad에서 `NEXT_PUBLIC_MOCK=1 next dev -p 3123`으로 띄워 데스크톱 라이트·다크, 390px 모바일, 키보드 포커스, 확인 창을 추가 캡처했다(`scratchpad/gm-review/shots/`). 워크트리 파일은 바꾸지 않았고 dev 서버는 종료했다.
- 경로는 `apps/web/` 기준이다.

## 총평

전체 톤은 Apple 방향에 맞다. 보라 그라데이션·반짝이·로봇 아이콘·글래스모피즘 남용·카드 반복 대시보드가 없다. 말풍선 틴트(p1 오렌지·p2 그린·p3 퍼플)와 이름 표시가 일관되고, 결정 사항은 구분선 목록이며, 리포트는 한 열 문서다. 지원자 화면 용어("정할 항목·결정 사항·이걸로 정하기·정했어요")는 지켰고, 디브리핑 전 지원자 코드·mock에서 페르소나 유형이 나오지 않는다(grep 0건, 테스트에서만). 다크 모드(토론방·기획안·디브리핑·관리자 리포트)도 대비와 틴트가 무너지지 않는다.

남은 문제는 대부분 **캡처 위생**(개발 칩, 전환 중 촬영, 인쇄 PNG 깨짐)과 **규칙 위반 몇 건**(진행바 결과 글자 없음, 실제 시계 저장 시각, R1 고정 문장 변형, 리포트의 코드 id)이다. 모두 고치기 쉽다.

## Blocking (최종 캡처 전에 고칠 것) — 7건

### B1. 관리자 캡처에 개발용 "data ◂" 칩이 찍혀 있다
- 화면: `mock-ui-admin-…/01-position-create.png`, `02-candidates.png`, `03-report-summary.png`, `08-record-highlight.png` 오른쪽 아래. 390px에서는 지원자 목록 내용 위를 덮고 Next 개발 표시 "N" 배지도 겹친다.
- 원인: `components/dev/data-toggle.tsx`(no-print만 있고 화면에서는 보임). `e2e/admin-capture.spec.ts:37` `shot()`이 지원자 캡처 스크립트처럼 숨김 스타일을 넣지 않는다.
- 고칠 것: `admin-capture.spec.ts`의 `open()` 뒤에 `page.addStyleTag({ content: "[data-dev-toggle],nextjs-portal{display:none!important}" })`를 넣고, DataToggle 루트에 `data-dev-toggle`를 붙인다(또는 `?capture=1`이면 렌더하지 않게 한다). 그다음 관리자 캡처를 다시 뜬다.

### B2. `05-report-adjust.png`가 전환 중에 찍혀 수준 2·3이 둘 다 선택된 것처럼 보이고, 04·05 둘 다 왼쪽 끝이 잘렸다
- 원인: `admin-capture.spec.ts:62-64`가 `radio "수준 3"`을 누르자마자 요소 스크린샷을 뜬다. `components/admin/segmented.tsx:42`의 `transition-colors duration-150` 때문에 앞 선택의 테두리가 남는다. 요소 스크린샷이 `#dim-…` 경계에 딱 맞아 접힘 화살표(⌄)와 오른쪽 테두리가 잘린다.
- 고칠 것: 클릭 뒤 `waitForTimeout(250)`. 요소 스크린샷 대신 `page.screenshot({ clip: 경계 + 16px 여백 })`. 메모를 한 줄 채워 [저장]이 켜진 상태도 1장 더 뜨면 "메모 필수" 흐름이 그림에서 읽힌다.

### B3. `07-print-preview.png`가 깨진 이어붙임이다
- 화면: 이미지가 "존중하는 반대" 중간에서 시작하고 아래쪽(약 16,800px)에서 리포트 머리가 다시 나온다. `emulateMedia(print)` + `fullPage`의 스크롤 이어붙임 문제다. 반면 `07-print-preview.pdf`(11쪽)는 정상이다.
- 고칠 것: PNG는 버리고 PDF 1~2쪽을 이미지로 바꿔 쓴다(`pdftoppm -r 144 -f 1 -l 2`). 같은 PDF 2·3쪽 아래에 큰 빈칸이 생기는 문제는 N4에 적었다.

### B4. 기획안 저장 표시가 실제 시계("17시 26분 9초 저장됨")라 같은 화면의 회의 시각(09:46)과 부딪친다
- 위치: `components/debate/use-session.ts:47`(`toLocaleTimeString("ko-KR")`), `proposal-editor.tsx:64-65`. 캡처 `08-proposal.png` 아래.
- 지원자 화면 시각은 남은 시간과 메시지 타임스탬프의 회의 시각, 두 가지뿐이어야 한다(design.md:20·129, R7). 실제 시계는 제3의 시간 체계라 그림 7-3을 읽는 사람이 헷갈린다.
- 고칠 것: "저장됨"(방금이면 "방금 저장됨", 1분 넘으면 "n분 전 저장됨")처럼 상대 표기로 바꾼다. 굳이 시각을 쓴다면 회의 시각 변환(`officeTime`)을 쓴다.

### B5. 디브리핑 R1 고정 첫 문장이 바뀌어 있다
- 위치: `mocks/fixtures/debrief.json:2` "…정답 없이 **각자의** 반응을 봅니다." 정본(design.md:210, R1 고정)은 "같은 채용 건의 모든 지원자가 같은 장면을 겪었고, 정답 없이 반응을 봅니다."
- 고칠 것: "각자의"를 지운다. 뒤의 "AI 동료들은 장면에 맞춰…" 문장은 별도 문장으로 두는 편이 좋다(첫 문장이 고정 문구와 정확히 같아야 함). 완료 기준(design.md:328) 항목이고 그림 7-4 맨 위에 나온다.

### B6. 상단 진행바의 지난 단계가 아이콘만 있고 "합의/시간 초과" 글자가 없다
- 위치: `components/debate/debate-view.tsx:41-47`. `aria-label`만 있고 화면에는 ✓/시계 아이콘만 보인다. 시간 초과 시계는 `text-muted`라 더 약하다.
- 정본: design.md:134 "지난 단계는 결과 아이콘 + 글자(합의/시간 초과)", design-system "색만으로 구분하지 않는다·아이콘 + 글자". 그림 7-1·7-2·7-3 상단에 모두 나온다.
- 고칠 것: 아이콘 뒤에 `<span className="text-caption text-muted">합의</span>`처럼 글자를 붙인다(예: "✓ 키워드 · 합의", "◷ 해결책 · 시간 초과"). 폭이 부족하면 단계 이름 오른쪽에 caption 크기로 둔다.

### B7. 리포트에 코드 id와 내부 용어가 보인다
- 위치: `fixtures/sample-report.json:279` 담당자 메모 "**m-08** 앞뒤에서…"(인쇄 PDF 3쪽 "메모 · m-08 …"). 판단 이유 문장 끝의 "(앵커 3)"·"(앵커 4)"(같은 파일 105·274·359행 등, `mocks/fixtures/report.json`도 같은 패턴. 04-report-evidence "판단 이유 … (앵커 4)").
- 정본: design.md:237 "채용 관계자가 바로 읽을 문장으로 쓰고 코드 id는 화면에 보이지 않는다".
- 고칠 것: 메모를 "09:06 발언 앞뒤에서…"처럼 바꾸고, "(앵커 N)"은 지우거나 "(수준 N 기준)"으로 바꾼다. 앞으로 평가 에이전트 출력에서도 앵커 표기를 걸러야 하므로 report-view에서 `/\(앵커 \d\)/`를 지우는 처리를 함께 두면 안전하다.

## Non-blocking (개선 권장)

### 지원자 화면
- **N1. 묶음마다 "이름 + 시각"이 붙어 시각이 겹친다.** `components/debate/chat.tsx:132-137`이 묶음 머리에 시각을 늘 넣는다. 그래서 가운데 시각 줄 "09:25" 바로 아래 "나 09:25"가 또 나온다(04·06 캡처). 정본은 묶음 머리에 이름만 두고 시각은 5분 간격·단계 경계의 가운데 줄과 hover다(design.md:142, design-system MessageBubble). 136행 `<span>{time}</span>`을 빼면 화면이 훨씬 iMessage처럼 조용해진다. 어차피 다시 캡처하니 B6과 함께 고치기를 권한다.
- **N2. 390px에서 토론 화면이 깨진다.** `debate-view.tsx:161` `min-w-[1024px]` 때문에 모바일에서 화면이 1024px로 축소되고, 우측 패널이 화면 밖으로 나가며 상단 바가 잘린다(`shots/m-04-debate-keyword.png`). 키워드 버튼이 다른 요소에 가려 눌리지 않았다(Playwright 클릭 30초 초과). PC 권장이고 시트 접기는 polish 항목이지만, 최소한 `lg` 미만에서는 "PC에서 열어 주세요. 진행 시간은 흐르고 있습니다" 안내를 띄우거나 우측 패널을 하단 시트로 접는 처리가 필요하다. 입장·동의·대기·디브리핑은 390px에서 넘침 없이 정상이다.
- **N3. 탭과 패널의 aria 연결이 끊겨 있다.** `debate-view.tsx:195-212`이 `Tabs`에 `content: null`을 주고 패널을 따로 그린다. 그래서 첫 탭만 빈 `tabpanel`을 가리키고(나머지 `aria-controls=null`), 빈 tabpanel이 Tab 키로 포커스된다. 실제 패널 div에 `role="tabpanel"`과 `aria-labelledby`를 주고 빈 패널은 없앤다.
- **N4(지원자 쪽 포커스).** 입력류 `chat.tsx:376`, `decision-panel.tsx:113`, `proposal-editor.tsx:53`이 `outline-none` + 1px 테두리 색 변경만 쓴다. 기획안 textarea는 하단 1px 선 색만 바뀌어 포커스가 거의 안 보인다. 전역 `:focus-visible`(globals.css:243, 2px accent)을 살리거나 `focus-visible:ring-2 ring-accent/40`을 쓴다. 버튼·탭·?는 2px accent 링이 잘 보인다.
- **N5. 토론방 메시지 목록에 `role="log"`가 없다.** 새 메시지를 스크린리더가 알리지 못한다(입력 중 표시는 `aria-live` 있음). `chat.tsx:269` 스크롤러에 `role="log" aria-live="polite"`.
- **N6. 입장 화면 문구가 15분 데모와 맞지 않는다.** 부제는 "15분 · …"인데 본문 `mocks/fixtures/entry.json:8`은 "60분 동안 이어서…"(01-entry). 대기 화면은 "마지막 3분 30초"라 데모 기준이다. 데모 mock의 entry_notice를 15분으로 맞춘다.
- **N7. 결정 사항 그림에 시간 초과 줄이 없다.** 04-decisions는 합의 2줄과 입력 1줄뿐이다. R7 시간 초과 결과(아이콘 + "시간 초과")가 그림에 드러나지 않는다. 아래 그림 매핑 참고.
- **N8. 임시 프로필 이미지가 회색 기본 사용자 실루엣이다.** 실루엣이라 "미완성"처럼 읽힌다. 정본상 임시이고 교체 예정이지만, 보고서용으로는 일관된 단색 일러스트나 이니셜 대체(자리 색)가 더 정돈돼 보인다.
- **N9.** 디브리핑 종료 설문 1~5 버튼이 sunken 바탕 위 muted 글자라 눌러야 하는 것처럼 보이지 않는다(10-debrief-full). 버튼 테두리나 surface 바탕을 준다. 확인 창(이걸로 정하기·제출)은 문구·버튼 순서·모션 모두 정본대로다.

### 관리자 화면
- **N10. 관리자 mock이 아바타 경로를 바꾸지 않아 리포트·기록에서 프로필 이미지가 404이고 이니셜로 대체된다.** `mocks/debate.ts:116-118`에는 `/assets/missions/.../avatars/` → `/mock-avatars/` 치환이 있는데 `mocks/admin.ts`에는 없다. 그래서 지원자 그림(실루엣)과 관리자 그림(색 이니셜)의 동료 표시가 다르다. 같은 치환을 admin mock에도 넣는다.
- **N11. 기록 화면의 고정 필터 바가 반투명이다.** `components/admin/record-view.tsx:123` `bg-canvas/95` 때문에 뒤 글자가 비친다(08-record-highlight 상단에 "09:08 김지원"과 "의"가 겹쳐 보임). `bg-canvas`로 불투명하게 한다(반투명은 상단 바에만, design-system).
- **N12. 인쇄 PDF 2·3쪽 아래에 반 쪽 넘게 빈칸이 생긴다.** `globals.css:387` `.print-break{break-inside:avoid}`를 차원 전체(`report-view.tsx:435`, 근거·맥락 포함)에 걸어서다. 차원 머리(이름·수준·확신도·판단 이유)에만 avoid를 걸고 근거 목록은 쪼개지게 한다.
- **N13. 참여자 줄이 "지원자 지원자A (표시 이름 김지원)"이다.** 별칭이 "지원자A"라 "지원자"가 겹친다(report-view.tsx:684 근처). "지원자A · 표시 이름 김지원"처럼 쓴다.
- **N14.** 샘플 리포트 설득/논리력 요약이 "수준 3 · 담당자 조정됨 · AI 판단 3"이라, 조정했는데 값이 같아 보인다. 데모 fixture에서 조정 결과가 요소 수준을 바꾸도록(예: AI 2 → 담당자 3) 하면 "재계산·담당자 조정됨"이 그림에서 읽힌다.
- **N15.** 날짜 표기가 섞여 있다: "10. 21. 10:00"(목록)과 "1월 19일 삭제 예정". 한 형식으로 맞춘다.
- **N16.** 390px 지원자 목록은 표가 `overflow-x-auto` + `min-w-[720px]`라 가로 스크롤은 되지만, 스크롤 단서가 없어 "할 수 있는 일" 열이 없는 것처럼 보인다. 오른쪽 페이드나 모바일 카드 행을 고려한다(관리자는 PC 전제라 낮은 우선순위). 리포트는 390px에서 넘침 없이 읽힌다.

### 확인했고 문제없는 것
- 수준 칩은 중립 톤이고 색으로 서열을 만들지 않는다. 확신도 낮음은 ⓘ + warning 글자 "근거 약함, 원문 확인 권장"이다. "설계된 장면" 칩은 머리·카드 장면·관련 카드에 모두 있다. 근거 펼침은 앞 5·뒤 3 맥락이고 근거 줄은 accent-soft로 강조된다. 맥락 참조는 "맥락" 칩과 흐린 처리로 구분된다. 조정은 메모가 비면 저장이 꺼진다. 총점·합계는 없다.
- 지원자: 남은 시간과 회의 시각이 한 줄에 같이 나오지 않는다. 시간 초과 안내는 R7 문구 그대로다. idea_credit 안내는 중립 한 줄이다. 토론 단계에서는 제출이 꺼져 있다. 종료 시 입력이 모두 잠기고 [나가기]가 뜬다.
- 모션은 160~200ms opacity 위주이고 깜빡임이 없다.
