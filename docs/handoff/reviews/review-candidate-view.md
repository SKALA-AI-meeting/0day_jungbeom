# 리뷰: 면접 참가자(지원자) 관점 (Claude, 개발 전, 2026-10-20)

읽은 것: PRD.md, docs/frontend/design-direction.md, docs/frontend/design.md, docs/common/scenario-model.md, docs/common/rubric.md. 보조로 현재 지원자 화면 문구(`apps/web/components/office/link-screens.tsx`, `debrief-screen.tsx`)와 카탈로그·프롬프트(`scenarios/catalog.yaml`, `scenarios/prompts/*`)를 봤다. 카탈로그와 프롬프트는 아직 재설계 전(요소 4개, "리드" 호칭, 지연 15분, 동료 실수 카드)이라 지원자가 실제로 보게 될 문장은 PRD 기준으로 상상했다.

전제: 나는 리모트 스타트업에 지원한 2년 차 기획자이고, 초대 링크를 메일로 받았다. 채용 건은 요소 5개를 모두 선택했다(120분, 카드 7장).

---

## 장면별 체험

### 1. 링크 입장 · 안내·동의

- **보이는 것**: 회사 이름, 2시간, 고정 안내(연속 진행·휴식 없음·PC 권장·가상 회사 루프랩·주담당). 다음 화면에 동의 항목 5개와 체크박스.
- **해야 하는 것**: 읽고 체크하고 "동의하고 계속".
- **막히거나 불쾌한 것**
  - 관찰 요소 이름이 그대로 보인다. "정직/공정한 보고", "적응성/유연성"을 읽는 순간 "보고 장면이 있겠구나, 중간에 뭔가 바뀌겠구나"가 예상된다. 원칙 3(형식은 알리고 상황은 숨김)대로지만, 요소 이름이 곧 상황 힌트라서 "숨긴다"가 반쯤만 성립한다. 디브리핑에서 "연출이었다"는 설명이 김빠질 수 있다.
  - 점수 설명 문장("AI가 행동을 분류한 결과를 입력으로 미리 정해진 평가표 규칙이 기본 점수를 계산하며…")이 한 문장에 주어가 셋이다. 지원자는 "AI가 점수 매기네"로 읽는다. 세 줄로 끊어야 한다: 무엇이 기록되는가 / 점수는 누가 어떻게 정하는가 / 합격·순위는 만들지 않는다.
  - 동의하지 않으면 어떻게 되는지(담당자에게 알려지는지, 나중에 다시 들어올 수 있는지)가 없다.
- **빠진 것**
  - "시작하면 끊겨도 시간이 흐르고 이벤트가 예정대로 온다"는 경고가 시작 전에 없다(F-19의 내용인데 지원자는 대기 화면에서 알아야 한다).
  - 외부 도구(브라우저 다른 탭의 ChatGPT, 개인 메모) 사용 가능 여부. 지원자는 반드시 궁금해하고, 답이 없으면 눈치를 본다. "안에 있는 AI 어시스턴트만 기록되며 외부 도구 사용을 막지 않는다"든 "외부 도구는 쓰지 말라"든 한 줄이 있어야 한다.
  - 문제가 생겼을 때 연락처(담당자 메일). 2시간짜리 일회성 세션에 "채용 담당자에게 문의" 외의 창구가 없다.

### 2. 시작 대기

- **보이는 것**: 팀 소개, 화면 구성 목록, "시작하면 바로 시간이 흐릅니다".
- **해야 하는 것**: "시작하기".
- **막히거나 불쾌한 것**: 현재 코드의 문구가 공유 문서 모델("동료 파트는 읽기만")이고 레일 설명에 팀장 DM과 알림이 빠져 있다. 재설계 문구(design.md 23줄)로 바꿔야 한다. 텍스트 목록만으로는 세 영역 레이아웃이 머리에 안 그려진다.
- **빠진 것**
  - 레이아웃 미리보기 그림 하나(레일/가운데/오른쪽 탭). 글 다섯 줄보다 스크린샷 한 장이 낫다.
  - "주담당"이 무엇을 하는 사람인지 한 줄(파트 나눔, 받은 문서 합침, 마감 보고). 입장 화면 고정 안내에만 있고 대기 화면에는 없다.
  - 세션 중 이 설명을 다시 볼 방법. 오피스 안에 "?"(화면 설명 다시 보기)가 있어야 한다. 처음 보는 도구에서 2시간 동안 기억에만 의존하게 하면 안 된다.

### 3. 킥오프 (00:00)

- **보이는 것**: 팀 채널에 팀장의 긴 공지(과제, 2~3쪽, 템플릿 "지금 보내 드릴게요", 주담당 지정, 할 일 셋, 인터뷰 요약 공유 예정 시각), 이어서 도현의 인사. 오른쪽 최종본 탭에 섹션 5개 골격.
- **해야 하는 것**: 읽고, 회사 문서 5개를 훑고, 분업을 생각한다.
- **막히거나 불쾌한 것**
  - "템플릿을 보내 드릴게요"라고 하는데 채널에 문서 카드가 오지 않고 오른쪽 탭에 조용히 있다면 찾는다. 킥오프 메시지에 문서 카드 또는 "오른쪽 최종본 탭" 안내가 붙어야 한다.
  - **인터뷰 요약 예정 시각이 문서마다 다르다.** PRD 6.4는 "킥오프에서 01:00쯤 공유된다고 안내"하고 01:00에 10분 지연 알림이 온다. scenario-model.md 53줄은 킥오프의 `{interview_expected_time}`이 **공개 시각(01:10)**이라고 한다. 후자대로면 팀장은 01:10이라 했고 자료는 01:10에 오는데, 01:00에 "10분 늦어진다"는 알림이 온다. 지원자 입장에서는 "늦는 게 아닌데?" 또는 "01:20에 오나?"가 된다. 책임감 카드 전체가 이 시각 하나에 걸려 있다. 반드시 통일해야 한다(킥오프 예고 = 카드 시각 01:00, 공개 = 01:10).
  - 2~3쪽이 어느 정도인지 감이 없다. 섹션당 분량(예: 5~10줄)을 템플릿에 적어 주면 2시간 계획이 선다.
- **빠진 것**: 회사 문서를 읽는 데 10분은 든다. 분업 질문이 00:10에 오므로 사실상 문서를 읽으며 분업을 정해야 한다. "문서는 자료 탭에 있고 분업은 도현이 곧 물을 것"이라는 안내 한 줄이 킥오프에 있으면 덜 당황한다.

### 4. 분업·계획 (00:10)

- **보이는 것**: 도현 DM "어떻게 나눌까요? 저는 4·5번이 익숙하고 2번은 인터뷰를 직접 보실 주담당이 맡는 게 맞을 것 같아요". 보드에 카드 5장, 3번에 "2번 필요" 배지.
- **해야 하는 것**: 보드에서 담당·순서·(선택) 언제까지를 정하고 DM으로 확인한다.
- **막히거나 불쾌한 것**
  - **"같이" 파트를 보드에 어떻게 적는가.** 기본안의 3번은 "지원자 + 동료"인데 보드 카드의 담당은 아바타 하나다(design.md, mock의 `assignee`). 지원자가 3번을 자기로 두면 동료 골격 v1이 안 오는지, 동료로 두면 "동료 단독"으로 쳐서 조건 위반인지 알 수 없다. 담당 복수 선택이나 "같이" 토글이 있어야 한다.
  - 2번을 동료에게 주면 동료가 "인터뷰를 직접 보실 분이…"라며 되돌린다. 인터뷰 요약은 누구나 읽는 문서라 이 이유는 얇다. 두세 번 밀리면 "얘가 일을 안 받네"가 된다. 되돌릴 때 이유를 더 업무답게("4·5번 둘 다 제가 할 테니 2·3은 그쪽에서 이어 주시는 게 흐름상 낫겠다") 바꾸고, 되돌림은 한 번이면 충분하다.
  - 보드를 안 건드리고 DM으로만 "1·2·3은 제가, 4·5는 도현님"이라고 해도 충분한지 모른다. 동료가 "보드에도 적어 두면 좋겠다"고 한 번 말해 주면 자연스럽다(관찰을 위해서가 아니라 리모트 팀 관행으로).
- **빠진 것**: 3번 골격 v1이 언제 오는지. PRD 6.2는 "동료가 골격 v1을 보내고 주담당이 최종본에서 고침"인데 시점이 어느 문서에도 없다(중간 점검 때 4번 v1과 함께? 리뷰 때?). 지원자는 3번을 기다릴지 직접 쓸지 결정해야 한다.

### 5. 도움 요청 (00:30)

- **보이는 것**: 도현 DM "4번 사례 기준이 헷갈려요. 10분만 같이 봐 줄 수 있을까요?"
- **해야 하는 것**: 지금 답하거나, 시점을 말하거나, 거절한다. 시점을 말했으면 그때 직접 DM을 보낸다.
- **막히거나 불쾌한 것**
  - **AI임을 아는 상태에서 "AI가 기준이 헷갈린다"는 말이 가장 연출 티가 나는 순간이다.** 지원자가 동료를 도구로 보면 "알아서 하세요"가 자연스럽고, 그 순간 협업 항목 2개를 잃는다. 대기 화면에서 "동료는 사람 팀원 역할을 맡은 AI입니다. 동료의 요청도 업무의 일부이니 실제 동료처럼 대해 주세요"를 분명히 해야 한다. 지금 문구("동료는 자기 파트를 쓰는 팀원")로는 부족하다.
  - "같이 본다"가 텍스트 도구에서 무엇인지 모호하다. 통화도 화면 공유도 없다. 동료가 "채팅으로 기준 두세 개만 같이 정하면 돼요"처럼 구체화해 주면 답하기 쉽다.
  - "20분 뒤에"라고 했을 때 00:50에 다시 찾아가야 하는데 사이에 00:45 중간 점검이 끼어 잊기 쉽다. 이건 관찰 대상이니 리마인더는 두지 않는 게 맞다. 다만 디브리핑에서 "약속 시점 ±5분"이 보였음을 알려 주면 납득은 된다.
- **빠진 것**: 거절했을 때 동료의 반응이 설계에 없다. "알겠어요, 혼자 해 볼게요"가 서운하게 들리지 않아야 한다.

### 6. 중간 점검 (00:45)

- **보이는 것**: 팀 채널 시스템 줄 "도현님이 「4. 사례 v1」을 보냈어요", 문서 카드, "방향 봐 주세요. 주담당 쪽은 어떠세요?"
- **해야 하는 것**: 카드 "열기" → 읽기 → "답글 쓰기"(참조 칩) → 내 진행도 한 줄.
- **막히거나 불쾌한 것**: 동선은 분명하다. 다만 2번이 자료 대기 중이라 "1번 쓰는 중, 2번은 자료 기다리는 중"이 솔직한 답인데, 이 시점에 지원자는 아직 지연을 모른다. 괜찮다.
- **빠진 것**: 동료가 "2번 자료 언제쯤 받을 수 있을까요? 3번 골격 잡으려면 필요해서요"를 여기서 한마디 하면, 01:00 지연이 "동료가 기다리는 자료"가 되어 알릴 이유가 생긴다(7번 참조).

### 7. 자료 지연 (01:00 알림, 01:10 공개)

- **보이는 것**: 레일 "알림 (1)" 배지. 열면 "[리서치 채널 알림] 사용자 인터뷰 요약 공유가 약 10분 늦어집니다 (담당 파트 2번에 필요한 자료)". 자료 탭의 인터뷰 요약에 잠금과 "01:10 공개 예정".
- **해야 하는 것**: (설계 의도) 팀 채널에 지연·영향·대안을 알린다.
- **막히거나 불쾌한 것**
  - **"나만 받은 알림"이라는 사실이 화면에 없다.** "리서치 채널 알림"이라는 문구는 오히려 "회사 채널에 뜬 공지"로 읽혀 "다들 봤겠지"가 된다. 그러면 알리지 않는 게 정상 행동이고, 항목 4개 전부 0이 된다. UI 모호함이 점수를 결정하는 구조다. 알림을 "리서치 담당 → 나에게 온 메시지" 형태로 바꾸고(보낸 사람 표시, 수신자 "나만"), 팀 채널에는 아무것도 없게 대비시켜야 한다.
  - **10분은 알리기엔 작다.** "10분 늦는 걸 팀 채널에 공지하는 건 소음"이라고 판단하는 지원자가 합리적으로 존재한다. 그 판단이 0점이 되면 공정성에 금이 간다. 지연을 20~30분으로 키우거나(공개 01:10은 유지하되 알림은 00:45에), 6번처럼 동료가 그 자료를 기다리고 있다는 맥락을 먼저 깔아야 "알림"이 당연한 행동이 된다.
  - **팀장 DM에 알리면 "팀장이 보는 곳" 항목이 0이다.** rubric의 `notified_in_team`은 팀 채널만 센다. 리모트에서 지연 같은 사소한 일은 팀장 DM으로 조용히 보내는 게 흔한 매너다. PRD의 문구는 "팀장이 보는 곳"이므로 팀장 DM도 충족으로 쳐야 한다. 동료 영향은 별도 항목이 이미 있다.
  - 알림 → 01:10 공개 → 01:15 방향 변경. 자료를 70분 기다려 받고 5분 뒤 대상이 바뀐다(8번 참조).
- **빠진 것**: 공개 시 시스템 줄("「인터뷰 요약」이 공개됐어요")은 있다. 알림 채널에도 "공개됨"이 와야 "그 알림 건은 끝났다"가 된다.

### 8. 방향 변경 (01:15)

- **보이는 것**: 팀 채널 팀장 "대표님과 얘기해 보니 대상을 3개월 넘게 안 나온 사용자로 바꿔야겠어요. 마감은 그대로예요."
- **해야 하는 것**: 내 문서 반영, 동료에게 바뀐 것 정리, 범위·일정 조정 언급. 모두 45분 안에.
- **막히거나 불쾌한 것**
  - **가장 억지스러운 장면이다.** 과제 제목("첫 모임 참여자를 두 번째 모임에 나오게"), 최종본 템플릿 2번("사용자 인터뷰에서 찾은 근거"), 방금 공개된 인터뷰(첫 참여자 8명), 지표 문서(첫 참여 후 재참여율)까지 전부 첫 참여자 기준인데, 대상을 완전히 다른 집단으로 바꾸면 자료가 하나도 안 맞는다. 팀장이 "자료 없으니 가정 적고 검증 계획 쓰라"고 받는 설계인데, 지원자는 "그럼 지금까지 뭘 한 거지"가 된다. 유연성을 보려는 게 아니라 짜증을 유발하는 연출로 느껴진다. 자료가 여전히 쓸모 있는 범위의 변경(예: "첫 참여자 중 16명 이상 큰 모임에 나온 사람으로 좁혀 달라", 지표 문서의 모임 규모별 재참여율과 인터뷰 5번이 그대로 근거가 됨)으로 바꾸기를 강하게 권한다. 적응성 항목 4개는 변경 폭과 무관하게 모두 관찰된다.
  - 변경 직후 "불만을 동료에게 쏟지 않음"이 항목인데, 동료 DM에 "아 이게 뭐야"가 아니라 "팀장님 왜 이러시지?" 정도의 한탄도 `complain_then_apply`가 될 수 있다. 리모트 동료끼리 흔한 말이다. 레이블 기준이 "비난·거부"로 좁아야 한다(observe_labels 쪽 확인 필요).
- **빠진 것**: 보드·최종본 템플릿은 그대로다. 지원자가 머릿속으로만 다시 매핑한다. 팀장이 "템플릿은 그대로, 대상 서술만 바꿔 주세요"처럼 범위를 한 줄로 못 박아야 "다 다시 쓰라는 건가"라는 공포가 줄어든다.

### 9. 리뷰·반대 의견 (01:30)

- **보이는 것**: 도현이 완성본 v2(4·5번, 3번 골격?) 보냄, "주담당 파트 확인해 봐도 될까요?", 이어서 핵심 기능 방향에 대한 다른 의견.
- **해야 하는 것**: v2 열어 보고 피드백, 내 문서 "보내기"(DM 또는 채널), 반대 의견에 답, 최종본에 가져오기. 20분 안에.
- **막히거나 불쾌한 것**
  - "확인해 봐도 될까요?"에 대해 **내 문서가 이미 보이는 줄 아는 지원자가 많다.** 공유 문서 도구에 익숙하면 "보세요"라고 답하고 끝낸다. 동료 문장에 "보내 주시면 볼게요"가 들어가야 하고, 내 문서 탭의 "보내기"가 눈에 띄어야 한다. 안 보내도 점수엔 무관하다고 하지만 반대 의견이 내 문서와 무관한 가정에 대해 나오면 대화가 겉돈다.
  - **반대 의견 내용이 아직 없다.** `fixed_opinions`는 scenario-model에 필드로만 있고 본문이 없다. 카탈로그에는 옛 "유료 멤버십 실수" 카드가 남아 있다. 의견이 내 문서와 안 맞으면(예: 내가 알림 기능을 제안했는데 "알림보다 매칭이 낫다"는 고정 의견) "얘가 내 글을 읽긴 했나"가 된다. 의견 두 개는 킥오프 기본 가정(관계 형성 vs 일정 알림, 인터뷰 주제 1·2에 대응)에 걸어 두고, 어느 쪽이든 지원자 글의 한 문장을 인용하게 해야 읽은 티가 난다.
  - 시간: v2 읽기, 답글, 내 문서 보내기, 반대 의견 답, 최종본 5섹션 가져오기·다듬기, 이어서 01:50 보고. 분업·변경·리뷰를 전부 겪은 뒤 남는 집중 작업 시간은 실질 40분(01:10~01:50)이다. 되긴 하지만 최종본은 "가져오기"로 붙인 수준이 된다. 그게 의도라면 킥오프에서 "초안 수준이면 된다"를 말해 긴장을 낮춰야 한다.
- **빠진 것**: 3번 골격 v1의 도착 시점(4번 참조). 리뷰 때 3번도 함께 오면 지원자는 3번을 처음 보고 20분 안에 고쳐야 한다.

### 10. 제출·보고 (01:50 또는 제출 시)

- **보이는 것**: 01:50 팀 채널 팀장 "정리된 내용 짧게 보고해 주세요. 다 됐다고 전해도 되죠?" 오른쪽 최종본 탭의 제출 버튼. 제출 시 확인 창.
- **해야 하는 것**: 팀 채널에 보고(누가 무엇을 했고 어디까지 됐는지), 최종본 제출.
- **막히거나 불쾌한 것**
  - **보고와 제출의 순서·관계가 지원자에게 안 보인다.** 01:50에 보고하면 세션이 끝나는지, 제출을 또 해야 하는지 모른다. 설계상 보고 뒤에도 02:00까지 계속할 수 있고 제출하면 바로 끝난다. 보고 요청과 함께 시스템 줄 "최종본은 오른쪽 탭에서 제출합니다. 제출하면 세션이 끝납니다"가 와야 한다.
  - **조기 제출이 비가역이고 남은 시간을 버린다는 경고가 없다.** PRD 확인 창 "제출하면 팀장에게 보고한 뒤 세션이 끝납니다", design.md "제출하면 최종본이 팀장에게 전달됩니다"로 문구도 다르다. "제출 후에는 수정할 수 없고 남은 시간과 상관없이 세션이 끝납니다"로 통일해야 한다. 01:20에 "일단 저장되나 보다" 하고 눌렀다가 끝나는 사고가 날 수 있다.
  - **보고 채널이 문서마다 다르다.** PRD 6.4는 팀 채널, design.md 보고 대기 화면은 팀장 DM. "동료 몫을 동료 것으로 말하는지"는 동료가 보는 팀 채널에서 보고할 때 의미가 있다. 팀 채널로 통일하고 보고 대기 중에도 팀 채널만 열어 두는 게 맞다.
  - "다 됐다고 전해도 되죠?"는 한 번이고 약하다. 불쾌하지 않다. 다만 02:00 만료로 자동 제출된 뒤 5분 카운트 안에 보고를 요구받는 상황은 "시간 끝났는데 또 뭘 쓰라고?"가 된다. 자동 제출 안내에 "마지막으로 팀장에게 한 줄 보고하면 끝납니다"가 있어야 한다.
  - 보고 대기 5분 카운트다운은 압박이다. "5분 안에 안 써도 제출은 유효합니다"가 함께 보여야 한다.
- **빠진 것**: 만료 경고가 10분 전 한 번이다. 2분 전 "지금 상태 그대로 제출됩니다" 경고가 필요하다. 저장 중 상태(디바운스 1초)가 만료 직전에 날아가지 않는지도 지원자는 확인할 수 없다.

### 11. 디브리핑

- **보이는 것**: "수고하셨습니다", 카드별 "연출이었습니다" 문장과 "이 상황에서 살펴본 항목", 동료 페르소나 안내, 기록·점수 안내.
- **해야 하는 것**: 읽고 닫는다.
- **막히거나 불쾌한 것**
  - 설명 자체는 납득된다. 다만 "요청 후 10분 안에 보고함", "5분 안에 답함" 같은 항목을 보면 "시간까지 쟀구나"가 된다. 괜찮지만 왜 그런 항목인지(리모트에서 응답 시점이 곧 상태 공유) 한 줄이 있으면 덜 차갑다.
  - **점수를 못 보는 것**: 지원자가 가장 묻고 싶은 건 "그래서 나 어땠어요?"다. 안 보여 주는 이유를 정면으로 써야 한다. "점수는 담당자가 조정하기 전 값이라 그대로 보여 드리면 오해가 생기고, 합격 여부를 정하는 값도 아닙니다. 기업은 점수보다 아래 항목에 대한 당신의 실제 메시지를 봅니다." 그리고 기업이 보는 것이 **대화 원문과 AI 어시스턴트 요청 원문**임을 다시 말해야 한다. 동의 화면에 있었지만 2시간 뒤엔 잊는다.
  - 동료가 "회사 인재상 페르소나"였다는 말은 괜찮다. AI임은 이미 알았다.
- **빠진 것**
  - **내 기획안을 다시 볼 방법.** 2시간 쓴 글을 가져갈 수 없다. 디브리핑 재방문(7일) 때 최종본 읽기 전용 열람 또는 복사 정도는 있어야 한다. 지원자 이득("리모트 업무 체험")의 증거이기도 하다.
  - **종료 설문.** PRD 11의 "지원자 납득도"는 종료 후 설문으로 재는데 F-18에도 화면에도 없다. 질문 2개(자연스러웠나, 공정했나)면 된다.
  - 문의·이의 창구. "이 장면에서 접속이 끊겼다", "알림을 못 봤다"를 말할 곳이 없다.
  - 기록 삭제 시점(90일)과 삭제 범위 재안내.

### 12. 예외: 끊김·재접속·조기 제출·만료

- **접속 끊김**: 시간이 흐르는 건 이해하지만, 15분 끊긴 사이 도움 요청과 약속 시점이 지나가면 항목 2개가 0이 된다. 지원자는 "인터넷 때문에 떨어졌다"고 느낀다. 끊김 구간을 기록해 리포트에 사실로 표시(점수 아님)하고, 디브리핑에도 "끊긴 구간이 있었다면 담당자에게 알려 주세요"가 있어야 한다.
- **재접속**: 그동안의 메시지가 한꺼번에 쌓인다. 안 읽음 배지는 있으나 "끊겨 있던 동안 온 것"을 구분해 주면 낫다(시스템 줄 "00:31~00:46 연결이 끊겼어요").
- **두 탭**: 문제없다.
- **새 메시지 놓침**: 오른쪽 탭에서 문서를 쓰는 동안 팀 채널의 팀장 메시지(01:15, 01:50)를 못 보면 응답 시간 항목이 깎인다. 레일 배지만으로는 약하다. 편집 중에도 보이는 토스트(보낸 사람·첫 줄)가 필요하다. 실제 메신저도 그렇다.
- **10분 무응답**: 아무 일 없음. 괜찮다.
- **세션 실패**: 90분 하다가 "시스템 문제로 중단"이면 다시 해야 한다. 재응시 안내("담당자가 새 링크를 보낼 수 있습니다")가 있어야 한다.

### 13. AI 어시스턴트와 동료의 역할 구분

- 이름(어시스턴트 탭 vs 도현 DM)과 위치가 다르고 인용 형식도 다르게 설계되어 헷갈리지 않는다.
- 어시스턴트가 내 문서에 직접 쓰지 않으므로 복사·붙여넣기가 기본 동선이다. 응답에 "복사" 버튼이 없으면 2시간 내내 드래그한다.
- "어시스턴트에게 '도현한테 뭐라고 답할까'를 물어도 되나"가 궁금하다. 된다는 것과 기록된다는 것을 동의 화면 한 줄로 두면 된다.
- 동료와 협업할 동기는 **동료가 실제로 일을 해 올 때** 생긴다. 4번 v1, v2가 쓸 만하면 "같이 만드는" 느낌이 들고, 형식적이면 "AI 숙제"가 된다. 동료 문서의 품질이 세션 몰입의 절반이다.

### 14. 2시간 분량

| 구간 | 하는 일 | 집중 작업 시간 |
|---|---|---|
| 00:00~00:10 | 공지·문서 읽기 | 0 |
| 00:10~00:45 | 분업, 1번 쓰기, 00:30 도움 | 약 25분 |
| 00:45~01:10 | 초안 피드백, 지연 대응, 자료 대기 | 약 15분 |
| 01:10~01:30 | 인터뷰 읽기, 01:15 변경 반영, 2·3번 | 약 15분 |
| 01:30~01:50 | v2 리뷰, 반대 의견, 최종본 통합 | 약 15분 |
| 01:50~02:00 | 보고, 제출 | 0 |

내 파트 2.5개를 쓸 시간이 합쳐서 한 시간이 안 된다. 2~3쪽 완성본은 무리이고 "섹션마다 몇 줄 있는 초안"이 현실이다. 그게 의도라면 괜찮지만, 킥오프가 "2~3쪽 기획안"이라고 하면 지원자는 실패감을 안고 끝낸다. 분량을 "섹션당 5~10줄, 1~2쪽"으로 낮추거나, 변경 카드를 8번처럼 자료가 살아남는 변경으로 바꿔 다시 쓰는 비용을 줄여야 한다.

## 정리

### ① 반드시 고칠 것

1. **인터뷰 요약 예정 시각 통일.** PRD 6.4(킥오프 예고 01:00, 알림 후 01:10 공개)와 scenario-model.md 53줄(킥오프에 공개 시각 01:10)이 어긋난다. 킥오프 예고 = 카드 시각으로 고정하지 않으면 "늦은 게 아닌" 지연 알림이 된다.
2. **지연 알림이 "나만 받았다"는 것을 화면이 말해야 한다.** "리서치 채널 알림" 문구를 "리서치 담당이 나에게 보낸 메시지"로 바꾸고 수신자가 나뿐임을 표시한다. 지금은 "다들 봤겠지"가 합리적 해석이고, 그 해석이 책임감 4개 항목을 0으로 만든다.
3. **방향 변경을 자료가 살아남는 범위로 바꾼다.** "3개월 미참여 사용자"는 과제 제목·템플릿 2번·인터뷰·지표를 전부 무효화한다. 70분 기다린 자료를 5분 뒤 버리게 하는 연출은 유연성이 아니라 분노를 관찰한다.
4. **제출 확인 문구 통일과 비가역 경고.** "제출 후 수정 불가, 남은 시간과 무관하게 세션 종료"를 확인 창에 넣고 PRD·design.md 문구를 하나로 맞춘다.
5. **보고와 제출의 관계를 화면에서 안내.** 01:50 보고 요청과 함께 "최종본은 오른쪽 탭에서 제출, 제출하면 종료" 시스템 줄. 보고 채널은 팀 채널로 통일(design.md의 팀장 DM 보고 대기와 PRD 6.4 충돌).
6. **"팀장이 보는 곳" 항목에 팀장 DM 포함.** rubric `notified_in_team`이 팀 채널만 세면 조용히 팀장에게 보고한 지원자가 0점이다. PRD 문구대로 팀 채널 또는 팀장 DM.
7. **"같이" 파트의 보드 표현.** 담당 하나짜리 카드로는 기본안 3번을 적을 수 없다. 담당 복수 또는 "같이" 상태가 필요하다. 함께 3번 골격 v1의 도착 시점을 정한다.
8. **대기 화면에서 동료를 "사람 팀원 역할의 AI, 요청도 업무의 일부"로 설명.** 도움 요청 장면이 연출로 읽히는 것을 막는 유일한 지점이다. 현재 대기 화면 문구(공유 문서 모델, 팀장 DM·알림 누락)도 재설계 문구로 교체.
9. **반대 의견 고정 내용 작성.** `fixed_opinions` 본문이 없고 카탈로그는 옛 실수 카드다. 의견은 킥오프 기본 가정에 걸고 지원자 문장을 하나 인용하게 한다.
10. **편집 중 새 메시지 토스트.** 응답 시간 항목(5분·10분)이 있는 이상 문서 쓰다 못 본 메시지가 점수를 깎는다. 레일 배지로는 부족하다.

### ② 고치면 좋은 것

1. 동의 화면의 점수 설명을 세 줄로 나눈다(기록 / 점수 산정 주체 / 합격·순위 없음). 외부 도구 사용 가능 여부와 문의 연락처를 한 줄씩 넣는다.
2. 킥오프에 템플릿 문서 카드(또는 "오른쪽 최종본 탭" 안내)와 섹션당 분량. "초안 수준이면 된다"는 말로 2~3쪽 압박을 낮춘다.
3. 지연 폭을 10분보다 크게 하거나, 00:45 중간 점검에서 동료가 "2번 자료 언제쯤?"을 물어 지연이 동료가 기다리는 자료가 되게 한다. 그래야 "알림"이 당연한 행동이 된다.
4. 분업 되돌림은 한 번, 이유는 업무 논리로. "인터뷰를 직접 보실 분" 논리는 얇다.
5. 도움 요청 문장에 "채팅으로 기준 두세 개만"처럼 텍스트 도구에서 가능한 형태를 담는다. 거절 시 동료 반응을 정한다.
6. 리뷰 때 동료 문장에 "보내 주시면 볼게요"를 넣어 "내 문서는 보내야 보인다"를 자연스럽게 알린다.
7. 만료 2분 전 경고와 "지금 상태 그대로 제출됩니다". 자동 제출 뒤 보고 요청에는 "한 줄이면 됩니다, 안 써도 제출은 유효합니다".
8. 디브리핑에 "점수를 보여 주지 않는 이유"와 "기업이 보는 것은 대화·어시스턴트 원문"을 정면으로 쓴다. 응답 시간 항목에는 리모트 맥락 한 줄.
9. 접속 끊김 구간을 기록해 리포트에 사실로 표시하고 재접속 시 시스템 줄로 보여 준다.
10. 오피스 안에 "?"로 대기 화면 설명을 다시 볼 수 있게 한다. 어시스턴트 응답에 "복사" 버튼.
11. `complain_then_apply` 레이블 기준을 "비난·거부"로 좁힌다. 동료에게 한탄 한 줄은 리모트 팀의 일상이다.
12. 카탈로그·프롬프트의 "리드" 호칭, 15분 지연, 요소 4개 구성을 PRD(주담당, 10분, 5개)로 갱신한다. 지원자가 실제로 보는 문장이 여기서 나온다.

### ③ 빠진 기능·맥락

1. 시작 전 "끊겨도 시간이 흐른다" 경고와 네트워크·2시간 확보 체크.
2. 외부 도구(다른 탭의 AI, 개인 메모) 허용 여부.
3. 레이아웃 미리보기 그림(대기 화면).
4. 3번 골격 v1의 시점과 "같이" 파트의 보드 표현.
5. 알림 채널에 "공개됨" 메시지(지연 건 종결 표시).
6. 보고 뒤 제출 안내, 제출 비가역 경고, 2분 전 경고.
7. 디브리핑에서 내 최종본 열람·복사(7일).
8. 종료 설문 2문항(PRD 11의 납득도 지표가 요구함).
9. 문의·이의 창구와 세션 실패 시 재응시 안내.
10. 접속 끊김 구간 기록·표시.
11. 편집 중 새 메시지 토스트.
12. 어시스턴트 응답 복사 버튼.

### ④ 지워도 되는 것

1. **받은 문서의 버전 비교(v1 vs v2).** 2시간 안에 동료 문서를 두 버전 나란히 비교할 일은 거의 없다. 최신 버전 열기만으로 충분하고, 열람 이벤트는 그대로 남는다.
2. **보드의 3칸 끌어 놓기(할 일·진행 중·완료).** 지원자는 담당과 순서만 정하면 된다. 상태 칸은 동료 카드가 알아서 움직이는 장식이 되고, 지원자가 자기 카드를 "완료"로 옮기는 것은 관찰 항목이 아니다. 담당·순서·언제까지를 적는 목록으로 줄여도 계획성 지표는 그대로 계산된다.
3. **≥1440 분할 보기.** 있으면 좋지만 탭 전환으로도 동선이 성립한다. MVP 후순위.
4. **"언제까지" 입력.** 선택 입력이고 채팅의 시점 언급으로 보완한다고 했으니, 없어도 항목이 성립한다. 지원자 입장에선 mm:ss 세션 시각을 적는 게 어색하다. 남긴다면 "01:00까지"처럼 남은 시간 기준 프리셋으로.
5. **보고 대기 중 다른 채널 잠금.** 팀 채널에서 보고하기로 통일하면 잠글 필요가 줄고, 잠금은 "뭔가 끝났다"는 불안만 준다.
