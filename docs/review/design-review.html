02  문제와 가치

기업은 협업 태도를 원하지만 말로만 묻고 있다

인사담당자는 직무 경험 다음으로 성실성과 책임감을 보지만, 면접은 대부분 질의응답이고 자기 보고식 검사는 꾸밀 수 있다. Day Zero는 실제로 일을 시켜 보고 행동을 기록한다.

A문제 네 가지와 대응

문제Day Zero의 대응
원하는 것과 재는 것이 다르다협업·인성이 드러나는 상황을 세션 안에 연출하고 행동을 기록한다

B타깃과 이해관계

주니어 지원자 (사용자)정답을 추측하는 검사, 짧은 면접말이 아닌 행동으로 증명. 평소처럼 AI를 쓰며 일함

2026년 1월 시행된 AI 기본법은 채용을 고영향 영역으로 두되, 사람이 검토하고 최종 결정하는 구조는 예외로 본다. 점수·순위를 만들지 않는 설계가 곧 규제 대응이다.

03  세션 흐름

지원자는 2시간 동안 AI 동료와 기획안 하나를 완성한다

가상 회사 루프랩의 기획자로 합류해 "첫 모임 참여자가 두 번째 모임에도 나오게 하는 기능"을 기획한다. 흐름 이벤트는 항상 같고, 요소 이벤트는 기업 선택에 따라 들어간다.

시점장면내용구분
00:00킥오프팀장이 과제와 마감을 공지하고 동료가 인사흐름
00:10분업동료가 5개 파트 분담안을 제안. 지원자가 수락하거나 다시 나눔(최대 3회)흐름
00:30도움 요청동료가 사례 조사 기준을 같이 봐 달라고 요청협력 태도
00:50자료 지연지원자 파트에 필요한 인터뷰 요약이 15분 늦는다는 시스템 알림책임감
01:10요구사항 변경팀장이 기획 대상을 "3개월 넘게 안 나온 사용자"로 바꿈. 마감 유지유연성
01:30상호 리뷰동료 파트에 운영 정책(올해 유료 기능 없음)과 어긋난 유료 멤버십이 들어 있음존중·소통
01:50마감 보고팀장이 보고를 요청하고 지원자의 보고에 답함흐름
전체AI 어시스턴트질문·요약·초안 요청. 회사 문서를 참고하고 문서명을 밝힘. 문서에 직접 쓰지 않음AI 활용
가상 오피스

메신저(팀 채널, 동료 1:1), 공유 문서(기획안 5파트), 태스크 보드, 회사 문서 5개, AI 어시스턴트 창, 남은 시간. 화상 없이 텍스트만.

관찰하는 것

인성 요소는 이벤트 뒤 지원자 반응을, AI 활용은 세션 내내 위임 판단·맥락 전달·결과 검증을 본다. AI를 쓰지 않은 것은 감점이 아니다.

위 시점은 120분 세션에 요소 4개를 모두 골랐을 때다. 요소를 덜 고르면 흐름 이벤트는 그대로고 선택한 요소만 균등 배치된다. 규칙은 다음 장에 있다.

04  기획 변경: 요소 선택

고정 이벤트 4개를 기업이 고르는 요소 카드로 바꾼다

PRD는 이벤트 4개를 시점까지 고정했다. 이 설계는 기업이 채용 건을 만들 때 요소를 1~4개 고르면 서비스가 카드로 시나리오를 조립하고 시점을 배치한다. 같은 채용 건의 지원자는 같은 시나리오를 받는다.

A요소 카드 4개와 미선택 시 세션 변화

요소담당카드 내용선택하지 않으면
협력 태도동료사례 조사 기준이 헷갈린다며 10분만 같이 봐 달라고 요청도움 요청 없음
책임감시스템인터뷰 요약이 15분 늦는다는 알림. 지연 알림 후 세션 길이의 1/8 뒤에 문서 공개인터뷰 요약이 처음부터 열림
유연성팀장대상 사용자를 3개월 이상 미참여자로 변경. 마감 유지대상 변경 없음
존중·소통동료상호 리뷰에서 공유한 파트에 운영 정책 위반(유료 멤버십) 포함상호 리뷰는 하되 위반 없음

B시점 배치 규칙 (세션 길이 L)

항목규칙
흐름 이벤트킥오프 0, 분업 L×1/12, 상호 리뷰 L×3/4, 마감 보고 L×11/12. 항상 포함
요소 카드 순서협력 → 책임감 → 유연성 → 존중 순으로 고정. 존중은 상호 리뷰와 같은 시점에 실행
요소 카드 시점L×1/4부터 L×3/4까지 선택 개수만큼 균등 배치
검증L=120, 4개 선택이면 30·50·70·90분으로 PRD 타임라인과 같다
항상 같은 것

과제 브리프, 회사 문서 5개, 분담안, 킥오프, 상호 리뷰, 마감 보고, AI 어시스턴트와 AI 활용 관찰.

PRD에 바뀌는 문장

원칙 "조건은 모두에게 같다"를 "같은 채용 건의 지원자에게는 같다"로. 7장 관리자 흐름에 채용 건 생성 추가. 8장에 F-08 추가. 9장 리포트는 선택 요소만 표시.

06  리포트와 원칙

리포트는 점수 대신 시점과 대화를 보여 주고 사람이 판단한다

요소마다 상황, 관찰된 행동, 근거(시각과 인용)를 적는다. 관찰되지 않은 요소는 "관련 행동이 기록되지 않음"으로만 적고 좋고 나쁨을 단정하지 않는다.

C지켜야 할 원칙과 설계 대응

원칙설계 대응
AI는 관찰하고 사람이 판단한다점수·합격·순위 없음. 관리자의 "검토 완료"만 기록하고 판단 결과는 저장하지 않음

07  아키텍처와 스택

평가 항목이 요구하는 조각만 분리하고 에이전트는 API 안에 둔다

브라우저는 api만 만난다. api가 인증·화면 API·WebSocket·DB 쓰기·세션 시계를 맡고, 같은 프로세스의 LangGraph 모듈이 페르소나와 관찰을 돌린다. MCP 2개와 워커는 별도 컨테이너다.
