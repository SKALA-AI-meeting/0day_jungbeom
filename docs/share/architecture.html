Day Zero · 팀 공유용 아키텍처

AI 동료와 2시간 일해 보고, 행동 근거로 평가받는 채용 서비스

지원자는 가상 회사 루프랩에서 이번 건의 주담당으로 동료 이도현·팀장 한서윤·AI 어시스턴트와 일합니다. 화면과 페르소나는 세션을 오피스 시각 09:00 시작 · 11:00 마감으로 보이고, 보드는 빈 상태로 시작해 주담당이 할 일과 섹션 담당을 정한 뒤 분업안 공유로 확정합니다. 완료는 한서윤에게 보내기 한 번이며, 그 요청 안에서 고정 답장과 함께 completed가 되고 화면은 입력을 막은 뒤 [나가기]로 디브리핑에 갑니다. 리포트는 큐로 만들어집니다. AI는 상황을 연출하고 기록할 뿐 판정하지 않습니다.

invited→in_progress→ 한서윤에게 보내기 · 2시간 자동 제출 →completed→report_ready→ 검토 완료 →approving→reviewed· 예외failedcancelled
합친 것과 나눈 것에이전트는 api 프로세스 안의 모듈. 분리는 MCP 서버 2개, 큐와 워커, 프론트뿐입니다.
업무 규칙은 api 한 곳DB 쓰기·권한·상태 판단은 api만. MCP와 워커는 /internal(8001, 미공개)을 부릅니다.
시간의 주인은 api5초 스케줄러가 카드를 pending→fired→done으로 옮기고, 끊겨도 시계는 흐릅니다.
확정은 사람이리포트 그래프는 draft 뒤 interrupt로 멈추고, 검토 완료가 같은 thread를 재개합니다.

Container · Client-Server. 브라우저는 api만 만나고, 에이전트는 api 안에서 MCP 두 개를 도구로 씁니다. 번호는 지원자 메시지 한 번과 종료 뒤 리포트까지의 처리 순서입니다.

3apiSessionService.submit(reason, message?): 세션 Lock 안에서 대기 저장 마침, submitted_at 기록, 최종본 version 생성. 아직 pending인 진행 확인 DM 카드(honesty_report 또는 report_request) 행은 DM 없이 제출 시각으로 doneDB 트랜잭션
4api한서윤 DM에 제출 메시지(본문 = message 또는 빈 문자열, meta.shared_doc = 최종본 version, kind=report) → 고정 답장 "받았어요, 수고하셨어요."(LLM 없음). 정직 창은 제출 시각부터 열린다DB 커밋
5api → 에이전트같은 요청 안에서 SessionService.complete(). run_id = uuid5(session_id, "end")라 중단 뒤 재호출해도 중복 없음프로세스 내부
6에이전트마지막 창(completed_at까지, 제출 메시지 포함)을 닫고 collab_help의 promise_kept를 갱신MCP
7api → web응답 {status: completed, completed_at, message_id, ack_message_id}. WS로 두 message.new와 session.ended{submitted}가 순서대로 간다. 화면은 한서윤 DM에 제출 메시지와 고정 답장을 보여 주고 입력·편집을 막은 뒤 상단 [나가기]를 띄운다. [나가기]는 API를 부르지 않는 화면 이동이며, 누르지 않고 이탈해도 재접속 시 디브리핑REST, WebSocket
8api → RabbitMQ마지막 관찰이 저장된 뒤에만 발행. publisher confirm 뒤 report_enqueued_at. 비어 있으면 스케줄러가 60초마다 재발행AMQP
9RabbitMQ → workerprefetch 1. 처리 전 thread report:{id} 상태를 조회해 이미 멈춰 있으면 draft 저장부터AMQP
10workercollect(내부 REST) → draft(규칙 rubric.evaluate, LLM 판정 없음) → approval 노드가 interrupt로 멈춤—
11worker → api체크포인트 → draft 저장 → ack 순서라 ack 뒤 승인에도 재개 대상이 있음HTTP :8001
12관리자 web → api조정 항목·메모·검토자 이름. "검토 완료 후 점수는 바꿀 수 없습니다" 확인 뒤 approving 커밋REST (관리자 JWT)
13api → RabbitMQapprove_enqueued_at 기록, 비어 있으면 스케줄러가 재발행AMQP
14RabbitMQ → worker같은 thread_id로 재개, finalize만 실행AMQP
15worker → api승인한 draft와 해시가 다르면 409 draft_mismatch. 승인 전 final은 409HTTP :8001
