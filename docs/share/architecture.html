2시스템 아키텍처

브라우저는 api만 만나고, DB 쓰기도 api만 합니다. MCP와 워커는 api의 내부 포트를 부릅니다.

핵심 설계 포인트

  • DB 쓰기는 api만. business-mcp와 워커는 api의 /internal(8001, 미공개, X-Internal-Token)을 부릅니다. 예외는 각자 thread의 체크포인트와 rag-mcp의 doc_chunks.
  • 시간의 주인은 api. 5초 스케줄러가 때가 된 이벤트를 pending→fired→done으로 옮기고, 재시작하면 fired 이벤트를 같은 run_id로 다시 실행합니다(메시지는 run_id·seq로 멱등).
  • 에이전트는 자극에 반응하는 함수. 지원자 메시지·이벤트 도래·세션 종료마다 그래프를 한 번 실행하고 체크포인트를 남깁니다. 세션 하나 = thread 하나, 세션 Lock으로 직렬.
  • 시나리오는 데이터. 채용 건을 만들 때 카드·회사 문서·프롬프트를 positions.scenario에 복사하고 catalog_version 해시로 고정합니다. 같은 채용 건은 같은 상황을 같은 시점에 겪습니다.
  • 리포트는 큐로, 확정은 사람이. 종료 → report.generate → draft에서 interrupt → 담당자 "검토 완료" → report.approve가 같은 thread를 재개해 final 저장.
  • AI는 판정하지 않음. guard가 점수·합격·연출 표현을 고정 안내문으로 바꾸고, 점수는 평가표 규칙 산출값과 담당자 조정값뿐입니다.

3세션 흐름 타임라인 (120분, 요소 4개 선택)

흐름 카드는 항상 들어가고, 요소 카드는 기업이 고른 것만 들어갑니다. 각 요소 카드의 관찰 창은 다음 요소 카드까지이고, 마지막 창은 제출·종료까지입니다.

AI 활용은 창과 무관하게 세션 전체에서 봅니다. 요소를 3개(협력·책임·유연)만 고르면 30·50·70분, 6분 시험 세션에 4개면 1.5·2.5·3.5·4.5분입니다.

4에이전트 그래프

세션 그래프는 phase와 자극으로 노드를 고르고, 관찰은 "규칙 지표 + 고정 레이블 분류"로 남깁니다. 점수는 워커가 규칙으로 세고 담당자가 확정합니다.

State (16필드)

session_id, phase, negotiate_round, division, scenario, current_element, window_start, stimulus, run_id, seq, handled_stimuli, recent_messages, summary, work_notes, tool_calls_used, token_budget_left, last_error. work_notes는 동료의 작업 기억(담당 파트, 리드 지시 누적, 합의, 말한 진행 상태)으로, 중간 초안과 완성본이 이를 반영해야 통과합니다.

페르소나 세 층

동료 이도현은 회사가 원하는 인재상으로 설정된 한 사람입니다. 성향(근거를 들어 말함, 막히면 먼저 공유 등)은 프롬프트로 자유롭게, 의무 액션(카드 실행·리드 결정 존중·자기 파트 작성·문서명 인용)은 결정적 노드가, 금지(평가 대상 행동 선점 5개, 점수·연출·미래 카드·미공개 문서)는 프롬프트·guard·픽스처가 지킵니다.
