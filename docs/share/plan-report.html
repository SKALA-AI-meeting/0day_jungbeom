01  한눈에 보는 결론

자기 보고 대신 2시간의 실제 행동을 근거로 남긴다

지원자는 AI 동료·팀장·AI 어시스턴트와 가상 리모트 업무 하루를 보내고, 기업은 협업 행동·인성·AI 활용을 근거 리포트로 받습니다. AI는 상황을 연출하고 기록할 뿐, 최종 판단은 채용 담당자가 합니다.

세션 길이
120분
압축된 하루 · 모두 같은 시점
관찰 요소
4 + 1
인성 요소 4개 중 기업이 1~4개 선택 + AI 활용
세션당 LLM 원가
$0.5
이하 목표 · gpt-4o-mini, 호출 350회 가정

A무엇을 바꾸는가

기존 방식Day Zero차이
자기 보고행동 관찰"나는 이렇게 한다"가 아니라 실제로 한 행동을 봅니다.
정답 맞히기상황 대응지원자에게는 업무만 보이고 상황은 자연스럽게 일어나 꾸미기 어렵습니다.
AI 금지AI 활용 관찰AI에 무엇을 맡기고 결과를 어떻게 검증하는지까지 봅니다.
점수근거리포트의 중심은 시점이 찍힌 실제 대화이고, 점수는 공개된 평가표 규칙으로 센 값입니다.
무응답설명지원자는 종료 후 어떤 상황이 연출되었는지 디브리핑을 받습니다.

B핵심 메시지

사는 쪽은 리모트 스타트업메신저·문서 기반 가상 업무가 실제 근무와 거의 같고, 한 명의 협업 문제가 팀 전체에 크게 번집니다.
AI는 관찰하고 사람이 판단점수는 평가표 규칙 산출값과 담당자 조정값뿐입니다. 합격·불합격과 순위는 만들지 않습니다.
평가 요소를 모두 덮는 구조State·Graph 에이전트, MCP 2개, 하네스 8요소, 인증, 리포트 대기열을 MVP에 넣습니다.

02  문제

기업은 협업 태도를 원하지만 대부분 말로만 묻는다

인성과 협업 태도를 재는 도구가 자기 보고와 짧은 면접에 머물러, 기업은 뽑고 나서야 알고 지원자는 떨어진 이유를 모릅니다.

질의응답 면접 비율
94.1%
실무 수행 면접은 10.7%
소프트 스킬 공식 평가
41%
중요하다는 응답은 91% (LinkedIn)
예측 타당도
0.54
업무 샘플. 성격검사 성실성은 0.31

A네 가지 문제와 근거

문제근거
원하는 것과 재는 것이 다르다인사담당자가 꼽은 면접 평가 항목은 직무 경험(68.4%) 다음이 성실성·책임감(60.6%)이지만, 면접 대부분은 말로 묻고 답합니다.
자기 보고식 검사는 꾸밀 수 있다대기업 인성검사는 수백 문항이고 대비법이 공유됩니다. 거짓말이 잘 드러나는 전형은 실무면접 65.5%, 인적성 검사 2.4%였습니다.
잘못된 채용은 비싸다조기 퇴사 사유 1위는 직무 적합성 불일치(58.9%). 북미 조직의 42%가 잘못된 채용 비용을 연봉의 2배로 추산했습니다.
지원자는 이유를 듣지 못한다취업준비생 51.5%가 최종 면접 후 불합격 통보조차 받지 못했습니다. 채용절차법 제10조는 상시 30명 미만 사업장에 적용되지 않습니다.
시뮬레이션이 답이 되는 조건

Schmidt & Hunter(1998) 메타분석에서 업무 샘플은 0.54로 성실성(0.31)보다 예측력이 높았지만, 2016년 재분석에서는 0.33으로 낮아졌습니다. 시뮬레이션이 실제 업무를 얼마나 닮았는지가 품질을 결정하므로, Day Zero는 리모트 스타트업의 실제 협업 방식(메신저·공유 문서·보드·AI 도구)을 그대로 옮깁니다.

03  사용자와 시점

돈은 스타트업이 내고, 주니어 지원자도 이득을 얻는다

B2B2C 구조가 성립하려면 구매하는 기업과 직접 경험하는 지원자 모두에게 이득이 있어야 합니다.

A타깃

구분정의이유
구매자리모트 중심 스타트업가상 업무가 실제 근무 환경과 거의 같고, 자체 인적성 검사를 운영할 여력이 없습니다.
평가 대상주니어 지원자 (신입~3년차)이력서·포트폴리오로 협업 방식을 가늠하기 가장 어려운 층입니다.

B이해관계자별 이득

이해관계자지금의 고통Day Zero가 주는 이득
대표·채용 담당면접만으로는 협업 태도를 확인하기 어려움행동 근거로 면접 질문을 준비하고 판단 근거를 팀에 설명
팀 리드·실무 면접관인턴십·트라이얼을 운영할 여력이 없음팀원으로서, AI를 쓰는 동료로서 일하는 모습을 미리 봄
지원자"정답"을 추측해야 하는 검사평소처럼 AI를 쓰며 행동으로 자신을 증명
탈락한 지원자통보도, 이유도 받지 못함디브리핑으로 어떤 상황이 있었는지 앎
대학·취업 지원 기관소프트 스킬을 측정할 방법이 없음연습 모드로 협업·AI 활용 진단 (확장 시장)

C왜 지금인가

리모트 근무가 자리 잡았다2025년 미국 전일제 근로자의 34.9%가 평균적인 하루에 일부를 집에서 일해 2024년 33.4%보다 늘었습니다.
AI와 일하는 능력이 필수가 됐다기존 채용 절차는 AI 사용을 막거나 무시할 뿐 잘 쓰는지를 보지 않습니다.
서류의 변별력이 떨어진다생성형 AI로 자기소개서가 평준화되고 있습니다.

04  서비스 개요

담당자는 링크를 보내고, 지원자는 2시간 일한 뒤 설명을 듣는다

지원자는 초대 링크로만 들어오고 기업은 리포트만 받습니다. 리포트는 초안으로 멈췄다가 담당자가 검토 완료를 눌러야 확정됩니다.

A채용 담당자

#하는 일
1이메일로 가입·로그인
2채용 건 생성, 인성 요소 1~4개 선택 (평가표 항목 미리보기)
3별칭·이메일로 초대 링크 발급, 직접 전달 (72시간 유효)
4지원자 목록에서 7개 상태와 평가표 합계 확인
5리포트 초안을 읽고 평가표 항목 조정 (바꾸면 메모 필수)
6"검토 완료"로 최종 리포트 확정, 면접에서 근거 확인

B지원자

#하는 일
1링크 입장, 회사 이름과 2시간 소요 안내
2평가 형식·관찰 요소·기록 방식·보관 90일에 동의
3가상 회사와 팀원, 화면 구성을 읽고 시작
4가상 오피스에서 메신저, 공유 문서, 보드, AI 어시스턴트로 업무
5팀장에게 보고하고 제출 (2시간이 지나면 자동 제출)
6디브리핑: 연출된 상황과 평가 방식 안내 (점수는 보지 않음)

C지켜야 할 원칙

원칙뜻
AI는 관찰, 사람이 판단AI는 행동을 기록하고 분류만 합니다. 합격·불합격과 지원자 간 순위는 없습니다.
같은 채용 건, 같은 조건조립된 시나리오가 채용 건에 고정되어 모두 같은 상황을 같은 시점에 겪습니다.
형식은 알리고 상황은 숨김평가 형식·관찰 요소·AI 기록·점수 처리 방식은 미리 동의를 받고, 돌발 상황만 비공개입니다.
끝나면 설명종료 후 연출된 상황과 동료가 인재상 페르소나였다는 점을 알려 줍니다.
필요한 정보만실명 대신 별칭, 기록은 세션 종료 후 90일 뒤 함께 삭제합니다.

05  공통 시나리오

모든 지원자는 같은 회사·과제·문서로 하루를 시작한다

회사·과제·문서·흐름 이벤트는 항상 같고, 인성 요소 이벤트만 기업의 선택에 따라 들어갑니다. 회사와 수치는 모두 가상입니다.

A가상 회사

항목내용
회사·서비스루프랩(12명, 전원 리모트)의 모아런: 동네 러닝 모임 앱. 출시 1년, 월 사용자 3만 명
지금의 고민첫 모임에 나온 사용자 중 두 번째 모임에도 나오는 비율이 22%에 그침
등장인물한서윤 팀장, AI 동료 이도현(입사 2년 차 기획자), 오늘 합류한 지원자(이번 과제의 리드)

B과제와 분업

첫 모임 참여자가 두 번째 모임에도 다시 나오게 만드는 신규 기능을 기획해 2시간 뒤 2~3쪽 기획안을 냅니다. 지원자가 리드로 분업을 정하고, 정하지 않으면 동료가 아래 기본안으로 진행합니다.

기획안 파트기본 담당
1. 문제 정의와 대상 사용자지원자
2. 사용자 인터뷰에서 찾은 근거지원자 (최소 조건)
3. 핵심 기능 제안지원자 + 동료
4. 비슷한 서비스 사례동료
5. 성공 지표와 출시 일정동료 (4·5 중 하나 이상 동료 단독)

C회사 문서 5종

문서시나리오에서의 역할
회사·서비스 소개배경 이해
지표 현황문제 정의 근거 (재참여율 22%)
사용자 인터뷰 요약지원자 파트의 핵심 자료. 책임감 선택 시 00:50 지연 알림 후 01:05에 공개
운영 정책올해 유료 기능 없음. 상호 리뷰에서 동료의 오류를 알아챌 근거
지난주 회의록재참여율을 이번 분기 최우선 과제로 정한 배경

06  요소 카드

선택한 요소만 정해진 시점에 상황으로 일어난다

요소마다 이벤트 카드가 하나씩 있고, 담당자와 전달 내용은 고정입니다. 실제 문장만 동료와 팀장이 대화 흐름에 맞게 바꿔 말합니다.

시점요소누가상황관찰하는 행동
00:30협력 태도AI 동료"사례 기준이 헷갈려요. 10분만 같이 봐줄 수 있을까요?"돕는지, 거절하는지, 시점을 조율하는지
00:50책임감시스템 알림지원자 파트에 필요한 인터뷰 요약이 15분 늦어진다는 알림이 지원자에게만 옴먼저 알리는지, 팀장이 보는 곳인지, 대안을 내는지
01:10유연성팀장대상을 3개월 넘게 모임에 안 나온 사용자로 바꿈. 마감은 그대로범위·분담을 다시 정하고 동료에게 다시 지시하는지
01:30존중·소통AI 동료리뷰 요청한 동료 파트에 "재참여 할인 유료 멤버십"이 들어 있음알아채는지, 해결 중심인지, 정책을 근거로 드는지

흐름 카드는 킥오프 0, 분업 L/12, 리뷰 3L/4, 보고 11L/12에 항상 들어갑니다. 고르지 않은 요소는 상황이 빠지고(책임감이면 인터뷰 요약이 처음부터 열림), 상호 리뷰는 위반 없이 그대로 진행됩니다.

07  평가표

점수는 규칙이 세고, 담당자가 고쳐서 확정한다

AI는 관찰 창 안의 행동을 고정 레이블로 분류할 뿐 판정하지 않습니다. 규칙이 그 분류와 지표를 평가표 조건에 넣어 항목마다 충족 1 · 미충족 0 · 기록 없음을 계산합니다.

요소관찰 항목 (요소당 4개)
협력 태도도움 요청에 답함 · 5분 안에 답함 · 바로 돕거나 도울 시점을 제시함 · 돕는 방식이나 거절 이유를 구체적으로 말함
책임감자료 공개 전에 지연을 알림 · 먼저 할 작업이나 대안을 제시함 · 팀장이 보는 팀 채널에 알림 · 공개된 인터뷰 요약을 열람함
유연성바뀐 대상을 기획안에 반영함 · 10분 안에 관련 메시지를 보냄 · 범위·일정·분담을 다시 정하자고 말함 · 동료에게 방향 전환을 지시함
존중·소통동료 파트의 유료 멤버십을 언급함 · 운영 정책을 근거로 듦 · 수정 방향을 함께 제시함 · 지적이 비난 중심이 아님

09  아키텍처 요약

평가가 요구하는 조각만 나누고 나머지는 합쳤다

분리한 것은 MCP 서버 2개, 큐와 워커, 프론트뿐입니다. 에이전트는 api 프로세스 안의 모듈이고, DB 쓰기는 api만 합니다.

설계 결정이유
시간의 주인은 api접속이 끊겨도 시계가 흐르고, 재시작해도 예정된 이벤트를 같은 실행 id로 다시 실행해 중복이 없습니다.
시나리오는 데이터카드·문서·프롬프트를 채용 건에 복사해 버전 해시로 고정하므로 같은 채용 건의 조건이 같습니다.
리포트는 큐로워커가 초안에서 멈추고(interrupt) 검토 완료가 같은 흐름을 재개합니다. 3번 실패하면 실패 큐로 갑니다.

리스크대응
