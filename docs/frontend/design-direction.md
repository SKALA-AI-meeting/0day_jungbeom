# 오피스 형태와 디자인 방향 (2026-10-20 초안, 의논 중)

순서: ① 협업 모델 → ② 평가가 요구하는 환경 → ③ 필요한 것만 → ④ 레이아웃 → ⑤ 레퍼런스에서 가져올 디자인. 확정되면 `design.md`의 "디자인"·"가상 오피스 레이아웃" 절과 `docs/prd-change-proposals.md` 재설계 절 4절(산출물 규칙)을 이 내용으로 바꾼다.

## ① 협업 모델: 문서를 주고받는다

리모트 협업의 실제 흐름은 "각자 자기 문서를 쓰고 → 보내고 → 받은 쪽이 열어 보고 피드백하고 → 고쳐서 다시 보내고 → 주담당이 받은 것들을 하나로 통합해 완성본을 만든다"이다. 공유 문서 한 장을 같이 고치는 모델 대신 이 흐름을 그대로 쓴다.

| 단계 | 지원자(주담당) | 동료 | 기록 |
|---|---|---|---|
| 분업 | 빈 보드에서 섹션에 연결된 할 일을 만들고 섹션 담당 5개를 정해 분업안 공유 | 팀 채널에서 묻고 따름, 채팅으로 정하면 섹션 담당을 채워 확정 | 보드 이벤트, 분업 스냅샷 |
| 작업 | 내 파트 문서를 씀 | 자기 파트 문서를 씀 | 각자 문서의 revision |
| 공유 | (원하면) 초안을 보냄 | 중간 점검 때 초안 v1을 채널에 보냄 | 공유 이벤트(문서·버전·채널·시각) |
| 리뷰 | 받은 문서를 열어 보고 피드백 | 리뷰 때 완성본 v2를 보내고, 주담당 문서에 의견 | 열람 이벤트, 문서에 매인 답글 |
| 수정 | 피드백 반영해 내 문서 수정 | 피드백 받으면 v3을 보냄 | revision, 공유 이벤트 |
| 통합 | **최종본**에 받은 문서를 가져와 정리 | — | 최종본에 어느 문서의 어느 버전이 들어갔는지 |
| 제출 | 최종본을 한서윤에게 보내기(메시지 선택) → 고정 답장 → 종료 | — | 제출 메시지 |

공유 문서 모델보다 나은 점:
- **작성자가 섞이지 않는다.** 문서마다 주인이 하나라 "누가 썼는가"가 사실로 남는다. 정직 카드의 대조가 쉽고, 낙관적 잠금·섹션 작성자 추적이 필요 없다.
- **읽었는가가 분명하다.** 받은 문서를 여는 것이 행동이라 "동료 초안을 읽고 반응"을 열람 이벤트로 센다.
- **통합이 주담당의 일로 보인다.** 최종본에 받은 문서를 가져오는 행동이 생겨 "최종본을 책임진다"가 자연스럽다. 보고와 최종본 내용의 대조도 가능하다.
- **고치고 다시 보내는 왕복**이 적응성(방향 변경 뒤 동료가 v3을 보내는가는 동료 몫이지만, 주담당이 다시 지시했는가)과 협업(피드백이 문서에 매임)을 선명하게 만든다.

같은 채용 건의 지원자가 같은 것을 받는다: 동료가 보내는 문서의 시점·버전·내용 골격은 카드가 정한다.

### 문서와 버전

- 문서 = 파트 하나 또는 최종본. 주인 한 명. "같이" 파트는 동료가 중간 점검 때 골격 v1을 보내고 주담당이 고쳐서 자기 것으로 통합한다(주인은 주담당으로 바뀌지 않고, 최종본에 들어갈 때 주담당이 편집).
- 보내기 = 버전이 하나 늘고(v1, v2…) 채널이나 DM에 문서 카드가 올라간다. 받은 쪽은 열어 보고 닫을 수 있다. 카드는 최신 버전을 열고, 이전 버전은 그때의 카드가 대화에 남아 있다.
- 최종본 = 주담당만 가진 문서. 섹션 5개 골격이 있고, 섹션마다 "받은 문서 가져오기"(최신 버전 기본, 다른 버전 선택 가능, 덮어쓰기만)와 직접 편집. 제출은 최종본을 팀장에게 보내는 것.
- 피드백 = 문서 카드에 매인 답글(스레드가 아니라 "4번 사례 v1에 대한 답" 표시가 붙은 일반 메시지). 인라인 코멘트는 두지 않는다.

## ④ 레이아웃

왼쪽 레일에 채널 목록과 오피스 시계를 두고, 메인 영역은 탭으로 대화·내 문서·보드·자료·어시스턴트를 전환한다(2026-10-21 결정, CX-08). 채팅하면서 작업하지 않으므로 영역을 나눠 쓰지 않는다.

```
┌ 레일 ─────────────────┬ 메인 ───────────────────────────────────────────────┐
│ 루프랩                  │ [대화 (2)] [내 문서] [보드] [자료] [어시스턴트]          │
│ # 재참여-기획           │ # 재참여-기획  👤서윤 👤도현 👤나                       │
│ @ 이도현  ●            │ 09:45 ─ 도현님이 「4. 사례 v1」을 보냈어요               │
│ @ 한서윤  ●            │ 09:45 도현  초안이에요, 방향 봐 주세요                   │
│ 알림 (1)               │   ┌ 📄 4. 비슷한 서비스 사례 · v1 ──────┐                │
│                       │   │ 열기                               │                │
│ 오피스 시각 09:47       │   └───────────────────────────────────┘                │
│ 마감 11:00 · 1:13 남음  │ 입력창                                               │
└───────────────────────┴─────────────────────────────────────────────────────┘

문서 카드 「열기」 → 대화 탭 위에 문서 보기:
┌ 레일 ─┬ 📄 4. 비슷한 서비스 사례 · 도현 · v1  [답글 쓰기] [최종본에 가져오기] [닫기 ✕] ┐
│       │ 본문 … (닫기 또는 레일의 채널 클릭으로 대화로 복귀)                              │
```

- 대화 탭은 "대화"와 "열린 문서" 두 상태. 열린 문서 위에 답글 쓰기(채널에 문서 참조가 붙은 메시지), 최종본에 가져오기, 닫기.
- 다른 탭에 있을 때 새 메시지가 오면 [대화] 탭에 배지, Toast로 보낸 사람·첫 줄.
- 내 문서 탭: 파트별 내 문서 목록(버전·보냄 여부)과 최종본. 문서를 누르면 편집, "보내기"로 채널·DM 선택. 최종본은 섹션마다 가져오기·편집과 완료 버튼.
- 보드·자료·어시스턴트 탭은 앞 절과 같음. 탭을 바꿔도 각 탭의 위치와 편집 중 내용은 유지되어 "받은 것 보면서 내 것 고치기"는 탭 전환으로 한다. 분할 보기는 polish 단계.

## 관리자 화면

- 채용 건 생성: 요소 카드 5장에 이름·한 줄 뜻·"이렇게 봅니다" 2~3줄만. 상황·시점은 숨김.
- 채용 건 생성은 기본 전체 선택, 요소를 빼면 차이 한 줄, 샘플 리포트 링크.
- 리포트: `design-system.md` 톤으로. 맨 위 요소별 한 줄 관찰·점수 요약표, 산출물 = 최종본(섹션별 "어느 문서 v몇에서 가져옴"·주담당 편집 여부, 편집은 동료 원문과 나란히) + 주고받은 문서 목록, 요소 섹션 안 카드 소섹션(접힘 기본), 항목마다 기록 기반/AI 분류 기반 표시, 근거마다 "기록에서 보기"로 전체 기록 화면의 해당 시점으로 이동. 인쇄 CSS로 PDF. 상세는 `design.md`.

## 기획 전환 제안서에 반영할 변경

- 4절 "공유 문서 전체 편집·낙관적 잠금·최종 통합 단계" → "문서 주고받기 모델·버전·최종본 가져오기". 낙관적 잠금과 섹션 작성자 추적은 필요 없어짐.
- 7절 기여 판정 → 문서 주인과 공유 이력으로 단순화. 정직 사실 입력 = 공유 이력·최종본 구성·보드 상태(미완료는 보드 기준).
- 데이터 모델: document_states(파트 5행) → documents(주인·파트·버전) + document_revisions(저장 이력) + document_shares + document_opens + final_document(섹션별 출처).

## 결정 (2026-10-20 사용자)

1. **최종본 형태는 킥오프에서 준다.** 팀장이 미션과 함께 최종 아웃풋 템플릿(섹션 5개 골격, 분량, 형식)을 전달하고, 주담당은 그 틀에 맞춰 주고받은 문서를 합치며 고친다. "가져오기" 버튼은 복붙 노동을 줄이는 보조 수단으로 두고 출처(문서·버전)를 기록한다.
2. **동료가 주담당 문서를 보자고 청하고 피드백한다.** 중간 점검 때 동료가 자기 초안 v1을 보내며 주담당 진행도 묻고("2번 자료 언제쯤 볼 수 있을까요?"), 리뷰 때 "주담당 파트 확인해 봐도 될까요? 보내 주시면 볼게요"라고 청한 뒤 받은 문서에 고정 내용의 다른 의견을 낸다(협업/조율의 반대 의견 카드가 이 장면). 주담당이 안 보내면 재촉하지 않고 보드·채팅의 방향을 근거로 의견을 낸다. 보냈는지 자체는 점수에 넣지 않는다.
3. **보드 카드에 "언제까지" 선택 입력.** 쓰면 계획성을 규칙으로 세고, 안 쓰면 채팅의 시점 언급을 LLM이 분류해 보완한다.
4. **팀장 DM 상시, 온라인.** 지원자가 과제에 대해 팀장에게 물을 수 있다. 팀장은 과제 맥락·조건·배경 질문에는 답하고, "뭘 쓰면 되나요·이게 맞나요" 같은 정답·판단 요청은 "주담당이 정해 주세요"로 돌린다(선점 금지와 같은 원칙). 평가·점수 언급은 guard가 막는다.
5. **호칭 "리드" → "주담당".** 같은 팀원이되 이번 건을 주로 맡아 이끄는 사람. 화면·브리프·리포트 문구에서 "리드"를 쓰지 않는다.

7. **보드가 분업의 정상 경로.** 2026-10-21 대체: 빈 보드에서 시작해 섹션에 연결한 할 일을 만들고 섹션 담당 5개를 정한 뒤 분업안 공유로 확정한다. 채팅으로 정하면 동료가 섹션 담당을 채워 확정한다. 계획성 관찰은 킥오프부터라 카드 전에 정한 계획도 센다.
8. **적응성 변경은 자료가 살아남는 범위.** 대상 사용자는 그대로 두고 핵심 기능을 "첫 모임 뒤 48시간 안 후속 모임 제안" 하나로 좁히고 출시 일정을 이번 분기로 당긴다. 인터뷰·지표·템플릿은 그대로 쓰고 3번·5번의 분담·내용만 재조정한다.
9. **전체 기록 화면과 리포트 재설계.** 세션 전체(채널별 대화·문서 보내기/열기·보드 변경·어시스턴트 호출)를 읽기 전용 타임라인으로 두고, 리포트의 근거·항목에서 "기록에서 보기"로 해당 시점을 하이라이트한다. 리포트는 `design-system.md` 컨셉으로 다시 설계한다(요약표·접힘 소섹션·기록 기반/AI 분류 기반 표시).
10. **샘플 리포트와 인쇄·PDF 둘 다 MVP.** 샘플은 픽스처 기반 정적 페이지(생성 화면·지원자 목록에서 링크), 내보내기는 인쇄 CSS. 회사 안 둘째 계정은 MVP 이후.
11. **AI 활용 라벨 제거.** 위임·맥락·검증 분류와 재사용 표기를 빼고 요청·응답·인용 문서·반영된 파트를 시간순 사실로만 보여 준다.
12. **지원자 화면 보강.** 지연 알림은 보낸 사람과 "나에게만"을 표시하고 공개되면 "공개됨" 줄. 완료는 "한서윤에게 보내기" 창("보내면 수정할 수 없어요", 2026-10-21 대체). 2분 전 경고. 대기 화면에 동료 설명(사람 팀원 역할의 AI, 요청·피드백도 업무)과 레이아웃 그림, 오피스 "?". 편집 중 새 메시지 토스트, 어시스턴트 응답 복사, 접속 끊김 시스템 줄. 받은 문서 버전 비교는 빼고 분할 보기는 polish로. 디브리핑에 점수 비공개 이유·종료 설문 2문항·최종본 열람 7일·문의 창구.
