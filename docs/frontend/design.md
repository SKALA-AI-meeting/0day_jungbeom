# 프론트 설계 (web)

Next.js App Router + Tailwind. 상태 관리는 React 상태와 fetch로 충분하다. UI 라이브러리는 `design-system.md`의 "라이브러리" 표에 있는 것만 쓴다.

## 디자인

- 문서 세 개의 관계: `design-direction.md`(협업 모델·환경·레이아웃·결정) → `design-system.md`(토큰·컴포넌트·라이브러리·모션) → 이 문서(화면별 규칙·경로·mock·완료 기준). 방향과 토큰은 참조만 하고 여기에 다시 적지 않는다.
- `emilkowalski/skills`는 `apps/web/.agents/skills/<이름>/SKILL.md`에 설치되어 있다(git 무시). 없으면 `npx skills@latest add emilkowalski/skills`.
- 단계별 스킬: web-redesign 트랙은 `emil-design-eng`(화면 구성), `pick-ui-library`(라이브러리 확인), `animate`(문서 열기·카드 이동·메시지 도착). 마무리에 `review-animations`, `break-ui`(긴 별칭, 빈 목록, 긴 메시지, 긴 문서, 요소 5개 카드 겹침).
- 서비스 이름과 로고는 Day Zero, Day-Zero, Day-0 중 자유롭게 변주한다. 가상 오피스는 "평가 중"이 드러나지 않게 메신저·문서 도구의 평범한 모습을 유지한다.
- API·WS 이름은 `docs/common/contracts.md`가 정본이다. 이 문서의 이름이 계약과 다르면 계약이 맞다.

안내·동의·대기·디브리핑 문구: 지원자 호칭은 "주담당"(같은 팀원이되 이번 건을 주로 맡아 이끄는 사람). 문서 설명은 한 줄: "각자 자기 파트 문서를 쓰고 보내며, 받은 문서를 열어 보고 답글로 피드백하고, 주담당이 최종본으로 합쳐 제출합니다."

### 안내·동의 화면

- 점수 설명은 세 줄로 나눈다: 무엇이 기록되는가(대화·문서·보드·어시스턴트 요청 원문) / 점수는 누가 어떻게 정하는가(AI가 행동을 분류하고, 미리 정한 평가표 규칙이 기본 점수를 계산하며, 담당자가 근거를 보고 최종 조정) / 합격·순위는 만들지 않는다.
- 외부 도구 한 줄: "다른 탭의 AI나 개인 메모 사용을 막지 않습니다. 기록되는 것은 이 화면 안의 어시스턴트 요청뿐입니다." 어시스턴트에게 "동료에게 뭐라고 답할까"를 물어도 되며 기록된다는 것도 한 줄.
- 문의 창구(담당자 이메일 또는 안내 문안의 연락처)와 동의하지 않을 때의 처리(세션이 시작되지 않고 담당자에게 알려지지 않음, 링크는 만료까지 유효) 한 줄씩.

### 대기 화면

- "시작하면 바로 시간이 흐르고, 접속이 끊겨도 멈추지 않습니다. 2시간과 안정적인 네트워크를 확보해 주세요."
- 팀 소개: 한서윤(팀장, 항상 온라인, 과제 맥락은 답하되 정답·판단은 주담당에게 돌림), 이도현(동료). 동료 설명은 "사람 팀원 역할을 맡은 AI입니다. 동료의 요청과 피드백도 업무의 일부이니 실제 동료처럼 대해 주세요."
- 주담당이 하는 일 한 줄: 파트 나눔, 받은 문서를 최종본으로 합침, 마감 때 팀장에게 보고.
- 레이아웃 그림 한 장(레일 / 가운데 / 오른쪽 탭, `design-direction.md` ④의 그림을 정적 이미지로)과 영역별 한 줄: 팀 채널·동료 DM·팀장 DM·개인 알림(나만 받음) / 대화와 받은 문서 열기 / 내 문서·보드·자료·어시스턴트.
- 문서 설명 한 줄(위 문구)과 "이 설명은 오피스의 ? 버튼으로 다시 볼 수 있습니다".

## 가상 오피스

레이아웃은 `design-direction.md` ④를 따른다. 레일 / 가운데 / 오른쪽 탭 세 영역. 컴포넌트 이름은 `design-system.md`의 표.

### 레일

- 항목: 팀 채널(`# 재참여-기획`), 이도현 DM, 한서윤 DM(팀장, 상시 온라인), 알림(지원자만 받는 `notice`), 마감 시계(Timer).
- 채널마다 안 읽음 수 배지. 선택 항목은 surface-sunken. 레일 클릭은 가운데를 "대화" 상태로 돌린다.
- 상단 ChannelHeader에 채널명·멤버 아바타 묶음(누가 보는가)·온라인 점. 알림 채널의 헤더는 "나만 받는 알림"으로 표시하고 멤버 아바타는 나 하나만 보인다.
- 헤더 오른쪽 끝 "?" 버튼: 대기 화면의 설명(팀·레이아웃·문서 흐름·주담당)을 대화 상자로 다시 보여 준다.

### 가운데: 대화 ↔ 열린 문서

- 두 상태. 기본은 대화(MessageRow·SystemLine·DocCard·입력창). DocCard의 "열기"로 DocViewer가 대화 위로 슬라이드되고, 닫기 또는 레일 클릭으로 대화로 복귀한다. 대화는 뒤에 그대로 있고 스크롤 위치를 유지한다.
- DocCard는 그 문서의 최신 버전을 연다. 이전 버전은 보낸 시점의 DocCard가 대화에 그대로 남아 있어 거기서 열 수 있다. 버전 비교 화면은 두지 않는다.
- DocViewer 헤더: 파트 칩·제목·주인·버전 칩(v2)·답글 쓰기·최종본에 가져오기·닫기. 열면 열람 이벤트를 보낸다(`POST /sessions/{id}/documents/{doc_id}/open {version}`, mock에서는 기록만).
- 답글: 입력창에 "4. 사례 v1에 답" 참조 칩이 붙은 일반 메시지(`message.send`의 `reply_to_doc`). 보내면 문서가 공유된 채널·DM으로 간다. 스레드·인라인 코멘트 없음.
- 최종본에 가져오기: 섹션 선택 팝오버 → 해당 섹션에 본문을 넣고 출처 칩("도현 v1에서")을 단다. 이미 내용이 있으면 "덮어쓰기" 확인(뒤에 붙이기 없음).
- 개인 알림 채널의 메시지는 보낸 사람(예: 리서치 담당 김민아)과 수신자 "나에게만"을 MessageRow 메타에 표시한다. 지연 건이 공개되면 같은 채널에 SystemLine "「인터뷰 요약」이 공개됐어요"가 와서 그 건이 끝났음을 보여 준다.
- 메시지 전송은 `client_msg_id`를 붙이고 `message.ack`로 확정 표시. `agent.progress`는 run_id별로 "이도현이 입력 중…", "자료 찾는 중…"을 표시. 재접속 시 `/state`의 `active_runs`로 복원.
- 오른쪽 탭에서 편집 중일 때 새 메시지가 오면 Toast(Sonner)로 보낸 사람·첫 줄을 보여 주고, 클릭하면 그 채널로 간다. 레일 배지만으로는 응답 시간 항목을 놓친다.
- 접속이 끊겼다 돌아오면 끊긴 구간을 SystemLine으로 남긴다("00:31~00:46 연결이 끊겼어요"). 구간은 서버가 WS 연결 기록으로 계산하고 리포트에 사실로 표시된다(점수 아님).
- 제출 버튼은 FinalDoc에 있고 확인 창을 거친다. 문구: "제출 후에는 수정할 수 없습니다. 팀장에게 보고한 뒤 남은 시간과 상관없이 세션이 끝납니다."

### SystemLine 종류

| 종류 | 예 |
|---|---|
| 문서 보냄 | 도현님이 「4. 사례 v1」을 보냈어요 / 나의 「2. 인터뷰 근거 v2」를 보냈어요 |
| 보드 변경 | 3. 핵심 기능 → 진행 중 (도현) / 담당: 나 + 도현 / 언제까지 01:00 |
| 분업 확정 | 분업이 정해졌어요: 1·2 나, 3 같이, 4·5 도현 |
| 자료 공개 | 「인터뷰 요약」이 공개됐어요 (자료 탭과 알림 채널 둘 다) |
| 입장·온라인 | 한서윤님이 들어왔어요 |
| 접속 끊김 | 00:31~00:46 연결이 끊겼어요 |
| 보고 안내 | 최종본은 오른쪽 탭에서 제출합니다. 제출하면 세션이 끝납니다 (보고 요청과 함께) |
| 제출·보고 | 최종본을 보냈어요 / 보고를 기다리는 중 (5분 안에 안 써도 제출은 유효합니다) |
| 마감 경고 | 마감 10분 전 / 마감 2분 전, 지금 상태 그대로 제출됩니다 |

### 오른쪽 탭

**내 문서**
- 목록: 파트별 내 문서(파트 칩·버전·보냄 여부·마지막 저장)와 최종본(★, "섹션 5 · 2 채움"). 동료 단독 파트는 목록에 없고, 동료가 보낸 문서는 가운데 DocCard로만 받는다. "같이" 파트는 동료가 중간 점검 때 골격 v1을 보내고 주담당이 최종본에서 고친다.
- 편집(DocEditor): 제목·본문 textarea, 1초 디바운스 저장(`PUT /sessions/{id}/my-documents/{part_no}`), 마지막 저장 시각. "보내기" 버튼은 눈에 띄게(내 문서는 보내야 동료가 본다) → 채널·DM 선택 팝오버 → 버전이 하나 늘고 해당 채널에 DocCard가 올라간다. 보낸 뒤 편집은 다음 버전 초안이 된다.
- 최종본(FinalDoc): 킥오프 템플릿의 섹션 5개. 섹션마다 출처 칩("도현 v2에서", "직접 작성", 가져온 뒤 편집하면 "도현 v2 + 편집")·가져오기(`POST /sessions/{id}/final/sections/{part_no}/import`, 받은 문서와 버전 선택, 최신 기본, 덮어쓰기만)·편집. 하단에 제출 버튼. 제출 전 대기 중인 저장을 끝낸다.
- 탭 전환으로 "받은 것 보면서 내 것 고치기"가 된다(가운데 DocViewer는 열린 채 유지). ≥1440 분할 보기는 polish 단계.

**보드**
- BoardColumn 3개(할 일·진행 중·완료)와 BoardCard 5장. 카드: 번호 칩·제목·담당 아바타(없음·나·도현·둘 다)·"언제까지"(선택)·의존 배지("2번 필요": 3번은 2번에 의존, 카탈로그 값).
- 세션 시작 시 5장 모두 담당 없음. 보드가 분업을 정하는 정상 경로다: 담당을 채우면 `PUT /sessions/{id}/tasks/{part_no} {assignee: candidate|colleague|both}`를 보내고, 5장이 다 차면 서버가 분업을 확정해 `division.confirmed`를 보내며 SystemLine "분업이 정해졌어요"가 남는다. 채팅으로 정한 분업은 동료가 같은 보드를 채우므로 결과는 같다. 확정 조건에 맞지 않으면(2번은 나, 3번은 도현 또는 같이, 4·5 중 하나는 도현 단독) 422 메시지를 카드 상세에 그대로 보여 준다.
- 끌어 놓기(dnd kit)로 칸 이동과 칸 안 순서 변경. 드롭 시 같은 PUT에 status·order·due_min을 보낸다.
- 카드 클릭 → 상세 패널(PropertyRow): 상태·담당·언제까지·의존·순서. "언제까지"는 남은 시간 기준 프리셋("30분 뒤", "마감 10분 전", 직접 입력)이고 저장은 세션 분(due_min)으로 한다. 담당 변경은 확정 뒤에도 가능하며 재배정으로 기록된다.
- 동료 카드의 변경은 `task.updated`로 반영되고 SystemLine을 남긴다.

**자료**
- DocList: 공개 문서는 제목·본문, 미공개는 잠금 아이콘과 "01:10 공개 예정". 시각은 서버의 `release_at_min`을 그대로 쓴다(요소 선택에 따라 달라지므로 고정값 없음). `document.released`로 열리고 SystemLine을 남긴다.

**어시스턴트**
- 요청·응답 목록, 인용 문서명 표시, POST 후 응답 대기 표시. 접히는 패널. 응답마다 "복사" 버튼(어시스턴트는 내 문서에 직접 쓰지 않으므로 복사가 기본 동선).

### 제출 → 보고 대기 → 디브리핑

- 보고 요청(11L/12)은 팀 채널에 온다("정리된 내용 짧게 보고해 주세요"). 함께 SystemLine "최종본은 오른쪽 탭에서 제출합니다. 제출하면 세션이 끝납니다".
- 제출(`POST /sessions/{id}/submit`) → `session.reporting {deadline_at}` → 보고 대기: 상단에 5분 카운트와 "5분 안에 안 써도 제출은 유효합니다". 채널 잠금 없음. 보고는 팀 채널 또는 팀장 DM에 쓴다. 문서·보드·가져오기는 서버가 409로 막으므로 버튼은 비활성.
- 이미 보고 요청이 나갔고 보고를 마친 뒤 제출하면 바로 종료. 보고 메시지를 보내거나 5분이 지나면 `session.ended` → 디브리핑으로 전환.
- 시간 만료 자동 제출도 같은 흐름. 자동 제출 안내: "시간이 끝나 지금 상태로 제출됐어요. 마지막으로 팀장에게 한 줄 보고하면 끝납니다."
- 타이머는 `ends_at` 기준으로 로컬 계산. 10분 전부터 warning 색. 2분 전 Toast "마감 2분 전, 지금 상태 그대로 제출됩니다".
- 재연결: WS 끊기면 3초 후 재연결하고 `/sessions/{id}/state`로 전체 갱신(문서·버전·공유·보드·열린 문서·`deadline_at` 포함). 세션 JWT가 없으면 `/s/{token}/resume`으로 재발급. `in_progress`와 `reporting` 모두 재입장 가능하고, reporting이면 보고 대기 화면으로 복원한다.

### 디브리핑

- "수고하셨습니다" 다음에 카드별 "연출이었습니다" 문장과 "이 상황에서 살펴본 항목". 응답 시간 항목 옆에 리모트 맥락 한 줄("리모트에서는 응답 시점이 곧 상태 공유입니다").
- 점수를 보여 주지 않는 이유를 정면으로: "점수는 담당자가 조정하기 전 값이라 그대로 보여 드리면 오해가 생기고, 합격 여부를 정하는 값도 아닙니다. 기업은 점수보다 위 항목에 대한 실제 메시지와 문서, 어시스턴트 요청 원문을 봅니다."
- 동료는 회사 인재상 페르소나였다는 안내, 기록 보관 90일과 삭제 범위 재안내.
- 내 최종본 읽기 전용 열람과 복사(디브리핑 링크로 7일).
- 종료 설문 2문항(세션이 자연스러웠나 / 공정했나, 5점 척도, 건너뛰기 가능).
- 문의·이의 창구(담당자 연락처)와 "접속이 끊긴 구간이 있었다면 담당자에게 알려 주세요". 세션 실패로 끝났으면 "담당자가 새 링크를 보낼 수 있습니다".

## 관리자 생성 화면

- 미션 블록: 이름·회사·산출물 한 줄(MVP는 기획안 1개 고정, 선택 UI 없음).
- 요소 카드 5장(계획성/꼼꼼함·협업/조율·책임감/성실성·적응성/유연성·정직/공정한 보고): 이름·한 줄 뜻·"이렇게 봅니다" 2~3줄. 상황·시점·카드 수·평가표 항목은 보여 주지 않는다. "(선택)" 꼬리표는 어느 카드에도 붙이지 않는다.
- 기본은 전체 선택이고 체크 해제로 뺀다. 카드를 빼면 그 자리에 차이 한 줄이 뜬다(예: 책임감을 빼면 "인터뷰 자료가 처음부터 열립니다", 적응성을 빼면 "팀장의 방향 변경이 없습니다"; 문구는 카탈로그의 요소별 값). 0개는 제출 버튼 비활성, 6개는 존재하지 않으므로 거부(계약 422는 그대로 표시).
- 안내 줄: "요소 구성이 같으면 같은 기준입니다. 다르면 만점이 달라 채용 건 사이 비교에 맞지 않습니다." 아래에 "샘플 리포트 보기" 링크(/admin/sample-report).

## 관리자 지원자 목록·초대

- 초대 폼: 별칭 입력 옆 설명 "지원자에게 이 이름으로 안내되고 세션과 리포트에 이 이름이 남습니다". 같은 채용 건 안 중복 별칭은 제출 전 막는다. 이메일은 목록에도 표시한다.
- 초대 만료는 "연장"(재발행)으로 풀고 재응시로 표시하지 않는다. 재초대(이전 세션과 연결)는 세션 실패·만료·취소 상태에서만 보인다.
- 목록 상태 묶음(필터로도 사용): 대기(초대됨·만료) / 진행(진행 중·보고 중, 시작 시각·종료 예정 시각) / 검토 필요(리포트 준비됨) / 완료(확정 중·검토 완료) / 문제(실패·취소). 만료·취소는 "초대됨(만료)"처럼 접미로 붙인다.
- 행마다 마지막 활동 시각·메시지 수. 실패 행은 담당자 행동 안내: 세션 실패면 "새 초대를 만들어 보내세요"(재초대 버튼), 리포트 실패면 "리포트를 다시 생성하세요"(`POST /admin/sessions/{id}/report/regenerate`).
- 시작 후 취소(중도 포기) 가능. 취소된 세션은 문제 묶음에 들어가고 리포트는 만들지 않는다.
- 점수는 충족·미충족·기록 없음 세 수를 나란히("충족 9 · 미충족 3 · 기록 없음 2"), 분모·비율 없이. 담당자 점수가 있으면 같은 형식으로 옆에. 점수 정렬·순위 없음.
- 행마다 삭제 예정일("12월 19일 삭제 예정", 세션 종료 + 90일). 상단에 "샘플 리포트 보기" 링크.

## 관리자 리포트 화면

`design-system.md` 톤 그대로: canvas 바탕, surface 카드, 선으로 구분, 색은 값·상태 칩에만. 채용 관계자가 바로 읽을 문장으로 쓰고 코드 값은 화면에 보이지 않는다.

**머리**
- 단계 배지(검토 대기 draft / 확정 중 / 검토 완료 final), 검토자 이름(final), 삭제 예정일, "인쇄" 버튼.
- 헤더 문구: "기본 점수는 관찰 기록을 평가표 규칙에 대입해 자동 계산한 값이고 담당자 점수는 검토자가 근거를 보고 조정한 값이며, 이 리포트는 합격·불합격을 판정하지 않습니다. 활동이 없어 판정하지 않은 항목은 점수에 넣지 않습니다."
- 요약표: 요소별 한 줄 관찰(`summary`)과 충족·미충족·기록 없음 세 수, 담당자 값이 있으면 옆에. 행을 누르면 아래 해당 요소 섹션으로 이동한다. 담당자는 요약에서 이상한 요소만 펼쳐 본다.

**① 산출물**
- 최종본 섹션 5개 본문(읽기 전용)과 섹션별 출처 칩(어느 문서 v몇에서 / 직접 작성 / 비어 있음). "도현 v2 + 편집" 칩은 누르면 동료 원문이 나란히 열려 무엇을 고쳤는지 보인다.
- 주고받은 문서 목록(파트·주인·버전·보낸 곳·시각·열람 여부), 분업 결정자(주담당/기본안), 최종 보고 메시지 원문.

**② 요소 섹션**
- 요소마다 소제목·한 줄 관찰·세 수. 안에 카드 소섹션(분업·계획, 중간 점검 등)이 접힌 상태로 나열되고, 소제목 줄에 항목 값 칩만 미리 보인다.
- 소섹션을 펼치면: 상황, 카드 발생 시각(이벤트 미발생이면 "이벤트 미발생(조기 제출)"), 관찰된 행동, 근거 목록, 평가표 항목.
- 근거: t_min·인용 또는 요약(문서 버전·열람·보드 변경·어시스턴트 호출)·직전 동료·팀장 메시지 1개를 맥락으로. 점수와 무관한 근거(창 밖 메시지·보조 사실)는 같은 목록에 "점수 무관" 칩. 근거마다 "기록에서 보기" 링크(`evidence[].record_ref` → `/admin/sessions/{id}/record#<record_ref>`, 해당 줄 하이라이트).
- 항목(요소당 4개): 문장·값 칩(충족 success / 미충족 muted / 기록 없음 subtle)·출처 칩 "기록 기반"(`basis: metric`) 또는 "AI 분류 기반"(`basis: label`). 응답 시간 항목은 실제 분 표시. draft에서는 담당자 값 토글과 메모 입력, 바꾸면 메모 필수, 메모는 관찰 문장 옆에도 표시.
- 기록 없음 사유는 코드 대신 책임 주체가 보이는 문장으로 매핑한다.

| 사유 | 화면 문장 |
|---|---|
| no_activity | 지원자 활동 없음 |
| classify_failed | 시스템: 분류 실패 |
| window_missed | 시스템: 메시지 지연 |
| document_missing | 시스템: 문서 미제공 |
| not_applicable | 해당 없음 |
| event_not_fired | 이벤트 미발생(조기 제출) |

- 정직 소섹션: 사실 입력(공유 이력·최종본 출처·미완료 파트·적응성 이후 버전)을 표로 보여 주고 "미완료는 보드 기준이며 지원자가 보드를 갱신하지 않았을 수 있습니다" 주석을 단다.
- 관찰 없음은 회색 안내 문구.

**③ AI 활용**
- 머리에 "판단 기준 없음, 면접 확인용". 요청·응답·인용 문서·반영된 파트를 시간순으로만 나열한다. 분류 라벨·비율·표기 없음. 각 호출에 "기록에서 보기" 링크.

**검토 완료**
- 하단 검토자 이름 입력란(필수)과 "검토 완료" 버튼. 확인 창: "검토 완료 후 점수는 바꿀 수 없습니다. 메모는 계속 추가할 수 있습니다." 조정 내용·전체 메모·검토자 이름을 POST /review로 보내고 "확정 중…"으로 바뀌며 폴링으로 final이 되면 검토 시각·검토자 표시.
- 확정 실패 시: "조정은 저장되어 있습니다. 확정만 다시 시도합니다." 안내와 재시도 버튼.
- final에서는 값 입력이 잠기고 리포트 전체 메모 추가만 열린다(`POST /admin/sessions/{id}/report/notes`, 최상위 `notes[]`로 표시, 항목별 메모 아님). 합격·등급·순위 UI 없음.

**인쇄**
- 인쇄 CSS로 브라우저 PDF. 접힌 소섹션 전부 펼침, 토글·버튼·링크 숨김, 머리 문구와 검토자·검토 시각 포함, 동료 원문 나란히 보기는 접음.

## 전체 기록 화면

- `GET /admin/sessions/{id}/record`로 받은 세션 전체를 한 타임라인으로: 채널별 대화(팀 채널·동료 DM·팀장 DM·알림), 문서 보내기·열기, 보드 변경·분업 확정, 어시스턴트 요청·응답, 접속 끊김 구간, 제출·보고. 줄마다 t_min·종류 칩·채널·주체.
- 필터: 종류(대화·문서·보드·어시스턴트), 채널, 주체(지원자·동료·팀장·시스템).
- 리포트의 "기록에서 보기"로 들어오면 `#<record_ref>` 줄로 스크롤하고 accent-soft 배경으로 하이라이트, 상단에 "리포트로 돌아가기".
- 읽기 전용. 편집·조정 없음. 인쇄 CSS 적용.
